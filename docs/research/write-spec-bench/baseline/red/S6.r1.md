# feat(shell): add `qq` one-off AI question command

## Summary

Add a `qq` shell command that sends a single, context-free question to the configured AI backend (`opencode`, `claude`, or `agy`) and prints the answer.

- Bare `qq` opens a `qq> ` prompt.
- `qq some question` passes the typed text verbatim, with no shell escaping needed.
- Backend and model settings are shared with `commit` under renamed `DOTFILES_AI_*` env vars.
- The shared helpers move into a new `lib/ai.sh`.

## Motivation / Context

The original request: a `qq` command that uses the same model env vars and settings as `commit`. Run with no parameters, it opens an input prompt for a single question, passes it to the configured AI agent as a one-off command, and returns the response. Also wanted: `qq this is a question` passing all params as the prompt, with a possible `qq 'this is a question'` form as a backup. The `c` alias has worked well passing args with minimal friction, so escaping quirks are a modest concern.

Existing overlap: `commit` in `lib/git.sh` already resolves:
- backend via `_dotfiles_commit_backend` (`DOTFILES_COMMIT_BACKEND`, default `opencode`; also `claude`, `agy`)
- model via `_dotfiles_commit_model` (`DOTFILES_COMMIT_MODEL`, per-backend defaults)
- timeout via `_dotfiles_commit_timeout` (`DOTFILES_COMMIT_TIMEOUT`, default 15s)
- spinner via `_dotfiles_spinner_wait`

`c` joins args with `"$*"`, which lets bash mangle special characters (redirects, globs, expansion) before the function runs. Detecting and erroring on such characters is not feasible for that reason, so `qq` reads the raw typed line from history instead.

## Requirements

### Shared AI settings (renamed)
- `DOTFILES_COMMIT_BACKEND` → `DOTFILES_AI_BACKEND` (same values: `opencode` default, `claude`, `agy`).
- `DOTFILES_COMMIT_MODEL` → `DOTFILES_AI_MODEL` (same per-backend defaults when unset).
- `qq` and `commit` resolve backend and model through the same shared helpers, so one setting drives both.

### Deprecated-name fallback
- If `DOTFILES_AI_BACKEND` / `DOTFILES_AI_MODEL` is unset but the old `DOTFILES_COMMIT_BACKEND` / `DOTFILES_COMMIT_MODEL` is set, use the old value and print a one-line deprecation warning naming the new variable to **stderr** (never stdout).
- When the new name is set, it wins and no warning is printed.

### Timeouts (per-command)
- `qq` gets `DOTFILES_QQ_TIMEOUT`, default **60s**.
- `commit` keeps `DOTFILES_COMMIT_TIMEOUT`, default 15s. Timeouts are not shared.
- Parsing: empty or non-numeric falls back to the default; `0` means no timeout (wait until the backend finishes; Ctrl-C still cancels).
- A small shared timeout parser, parameterized by variable name and default, serves both commands.

### Structure
- New `lib/ai.sh` holds the shared helpers, renamed to `_dotfiles_ai_*`:
  - `_dotfiles_ai_backend`, `_dotfiles_ai_model` (read `DOTFILES_AI_*` with the deprecated-name fallback)
  - `_dotfiles_ai_spinner_wait` (was `_dotfiles_spinner_wait`)
  - the shared timeout parser
  - `_dotfiles_qq` and the `qq` alias
- `lib/git.sh`: `commit` / `_dotfiles_commit_generate_message` call the `_dotfiles_ai_*` helpers. Commit-specific pieces (prompt, sanitize, `DOTFILES_COMMIT_TIMEOUT`) stay here.
- `lib/index.sh`: no change (it already sources every `lib/*.sh`).

### `commit` subcommands
- `commit backend X` now exports `DOTFILES_AI_BACKEND` (so it also switches `qq`).
- `commit status` also shows the `qq` timeout alongside the existing backend/model/timeout/available lines.

### `qq` behavior
- **No subcommands:** any input, e.g. `qq status of my PR`, is always a question.
- **Prompt wrapper:** a fixed instruction is prepended to the question, e.g. "Answer concisely for display in a terminal. Prefer short answers; use code blocks for commands." No env override.
- **Context-free:** pure Q&A with no repo/file access. The backend is invoked from a temporary empty directory and, where the CLI supports it, with tools disabled. Exact per-backend flags are to be verified against each CLI's current docs. The user's shell cwd is unchanged after `qq` returns.

### Runtime flow
1. Obtain the question: interactive shells use the raw history line; non-interactive calls use `"$*"`. If the result is empty, fall through to the `qq> ` prompt.
2. Resolve backend and model via `_dotfiles_ai_*`.
3. Launch the backend in the background from a temporary empty directory with wrapper + question.
4. Show the existing spinner on **stderr** (e.g. `Asking Opencode...`).
5. Print the answer to **stdout** as-is: multi-line, code blocks intact. Unlike `commit`, it is not truncated to one line; only leading/trailing blank lines are trimmed.
6. Clean up the temp dir and output file.

Stdout is answer-only; the spinner, warnings, and errors all go to stderr.

### No-arg input prompt
Bare `qq` shows `qq> ` and reads one line with `read -e -r` (readline editing; the text is not shell-parsed, so no escaping is needed). Enter submits. Empty input, Ctrl-D, or Ctrl-C exits without calling the backend.

### Args-as-prompt via raw history line
- Define `alias qq='_dotfiles_qq #'`. The trailing `#` makes bash treat the rest of the line as a comment, so it is not parsed, expanded, globbed, or redirected.
- `_dotfiles_qq` reads the current command from `history 1` (with `HISTTIMEFORMAT` neutralized), strips the history number and everything up to and including the `qq` invocation, and uses the remainder verbatim as the question.
- Result: `? * $VAR > < ; & | ' "` all pass through literally. A throwaway spike confirmed `what's up`, `a > b means what`, `$HOME`, `*`, `?`, `;`, and double quotes arrive verbatim, with no redirect file created.
- If the remainder is empty (bare `qq`), fall through to the `qq> ` prompt.

### Leading-space guard
`bash_profile` sets `HISTCONTROL=ignorespace`, so a command typed with a leading space is not recorded and `history 1` returns the *previous* entry (the spike showed this silently re-sending an older question). `_dotfiles_qq` must detect that the current command was not recorded and exit non-zero with an error telling the user to run bare `qq`. It must never send a stale history entry.

### Non-interactive fallback
In scripts / non-interactive shells (aliases and history inactive), `_dotfiles_qq` is called directly with real args and uses `"$*"`.

### Errors
Unlike `commit`, there is no manual fallback. Every error prints one line to stderr and exits non-zero:

| Case | Message (stderr) | Exit |
|---|---|---|
| Empty input / Ctrl-D / Ctrl-C at `qq>` | (none) | 1 (130 on Ctrl-C) |
| Leading-space guard trips | `qq: question not in history (leading space?); run bare qq instead` | 1 |
| Backend CLI not installed | `qq: <backend> not found` | 1 |
| Ctrl-C while waiting | `qq canceled` | 130 |
| Timeout | `qq: <backend> timed out after <N>s` | 124 |
| Backend fails / empty output | `qq: <backend> returned no answer` | 1 |

### Known limitations (documented, not worked around)
- **`!word`:** bash history expansion runs before the comment is recognized, so `qq is !important bad` fails with bash's own `event not found` and nothing is sent. This is visible, not silent.
- **Line continuation:** a trailing `\` is not supported in the args form (only the first physical line is recorded); use bare `qq`.
- **Piping:** in the args form, a trailing `| cmd` is part of the question. Piping the answer works only with bare `qq` or non-interactive calls.

## Non-goals
- Multi-turn chat / follow-ups
- Repo-aware answers (file reads, tools)
- Streaming output
- Markdown rendering
- Reading the question from piped stdin
- `qq` subcommands
- An env override for the wrapper prompt
- Working around `!word` history expansion

## Decisions log
- Share backend + model with `commit`, but `qq` gets its own timeout; shared env vars renamed to `DOTFILES_AI_*`.
- Old `DOTFILES_COMMIT_BACKEND` / `DOTFILES_COMMIT_MODEL` keep working as fallbacks, with a stderr deprecation warning.
- Shared helpers live in new `lib/ai.sh`; `commit backend X` exports `DOTFILES_AI_BACKEND`; `commit status` shows the qq timeout; `qq` has no subcommands.
- Bare `qq` reads a single line via `read -e -r` at `qq> `.
- Args form reads the raw typed line from history via `alias qq='_dotfiles_qq #'` + `history 1`, with a leading-space guard. Rejected: plain `"$*"` like `c` (silent redirects/expansion), and `"$*"` with a noglob alias (only fixes `?`/`*`).
- Fixed terminal wrapper prepended to the question, no env override.
- Context-free: run outside the cwd, tools disabled where supported.
- `DOTFILES_QQ_TIMEOUT` default is 60s, parsed like commit's.
