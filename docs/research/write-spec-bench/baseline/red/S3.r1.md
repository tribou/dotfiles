# Add `ghv` command: fzf browser for combined issues and PRs

## Summary

Add a `ghv` command that lists all issues and pull requests for the current repository in a single combined list using `fzf`. Selecting an entry runs the corresponding `view` command (`gh issue view` for issues, `gh pr view` for PRs).

## Motivation

Today, viewing an issue or PR requires knowing its number or running separate `gh issue list` and `gh pr list` commands. A single fuzzy-searchable list lets the user find and open either kind of item quickly, without having to remember which type it is.

## Requirements

1. `ghv` fetches issues and PRs for the current repo and merges them into one list.
2. Each row shows enough to identify the item at a glance:
   - Type indicator (e.g., `issue` / `pr`)
   - Number
   - State (open / closed / merged)
   - Title
   - Optionally: author, labels, updated time
3. The list is presented in `fzf` and is fuzzy-searchable.
4. On selection (Enter):
   - If the item is an issue, run `gh issue view <number>`.
   - If the item is a PR, run `gh pr view <number>`.
5. Cancelling `fzf` (Esc / Ctrl-C) exits cleanly with no output and no error exit code beyond what `fzf` conventionally returns.
6. Items are sorted by most recently updated first, with issues and PRs interleaved.

## Proposed approach

- Implement as a shell function or script in the dotfiles (location to be decided to match existing conventions for custom commands/aliases).
- Fetch with `gh issue list` and `gh pr list`, using `--json` with fields such as `number,title,state,updatedAt,author,labels`, and a sufficiently high `--limit`.
- Tag each record with its type, merge, and sort by `updatedAt` descending (e.g., with `jq`).
- Format as tab-separated lines and pipe to `fzf` with `--delimiter`/`--with-nth` so the type and number are retained for dispatch but display stays clean.
- Parse the selected line to extract type and number, then call the matching `gh <type> view <number>`.
- Optional: an `fzf --preview` that runs the same `view` command for the highlighted row.

## Open questions

- Which state filter applies by default: open only, or all states? Consider a flag (e.g., `ghv -a`) to include closed/merged items.
- Should `ghv` accept a repo argument (`-R owner/repo`) or only operate on the current directory's repo?
- Should the view open in the terminal (default `gh ... view`) or in the browser (`--web`)? A keybinding could allow both.
- What `--limit` is appropriate for large repos?
- Where does this live (shell function in the dotfiles vs. a standalone script on `PATH`), and does it need to work in both bash and zsh?

## Acceptance criteria

- [ ] Running `ghv` inside a GitHub repo opens `fzf` with both issues and PRs in one list.
- [ ] Rows are visually distinguishable as issue vs. PR.
- [ ] Selecting an issue runs `gh issue view <number>`; selecting a PR runs `gh pr view <number>`.
- [ ] Cancelling `fzf` produces no error output.
- [ ] Running outside a git repo or without `gh`/`fzf`/`jq` installed gives a clear error message.
- [ ] Behavior for an empty repo (no issues or PRs) is handled gracefully.
- [ ] Brief usage documented (README or inline comment/help text).

## Dependencies

- `gh` (authenticated), `fzf`, `jq`
