# Add `ghv` command: fzf browser for combined issues and PRs

## Summary

Add a `ghv` command that lists all issues and pull requests for the current repository in a single combined list using `fzf`. Selecting an entry runs the matching `view` command (`gh issue view` for issues, `gh pr view` for PRs).

## Background / Motivation

Browsing issues and PRs currently requires running `gh issue list` and `gh pr list` separately, then copying a number into `gh issue view` or `gh pr view`. A single fuzzy-searchable list removes that friction and makes it quick to jump to any item without remembering whether it is an issue or a PR.

## Scope

- A new `ghv` command (shell function or script, following the existing conventions in this dotfiles repo for where such commands live).
- Combined listing of issues and PRs from the current repo via the `gh` CLI.
- Interactive selection with `fzf`.
- Dispatch to the appropriate `view` command based on item type.

Out of scope: creating, editing, or closing items; cross-repo browsing; caching.

## Requirements

1. **Combined list**
   - Running `ghv` fetches issues and PRs for the repo in the current directory (e.g. `gh issue list` and `gh pr list`, or `gh search`/`gh api`).
   - Each line shows: type (issue/PR), number, title, and state. Labels, author, and similar fields are optional extras.
   - Type must be visually distinguishable (e.g. an `ISSUE`/`PR` prefix or color).
   - Default to open items. Include closed/merged items through an option (see Open Questions).
2. **Selection**
   - Items are fuzzy-searchable via `fzf`.
   - Pressing Enter on an entry runs `gh issue view <number>` for issues or `gh pr view <number>` for PRs.
   - Optionally, an `fzf` preview pane shows the item's details (`gh ... view` output).
3. **Behavior and errors**
   - Cancelling `fzf` (Esc/Ctrl-C) exits quietly with no error output.
   - If `gh` or `fzf` is not installed, print a clear message and exit non-zero.
   - If the current directory isn't a GitHub repo or `gh` isn't authenticated, surface the `gh` error and exit non-zero.
   - If there are no items, print a short message and exit 0.
   - Extra arguments are passed through to the `view` command where sensible (e.g. `--web`, `--comments`). Behavior to be confirmed (see Open Questions).
4. **Performance**
   - Issue and PR fetches should run in parallel or in a single query, to keep startup fast.
   - The list limit should be explicit and sufficient (e.g. `--limit 200`), and should be configurable.

## Acceptance Criteria

- [ ] In a GitHub repo with both issues and PRs, `ghv` opens an `fzf` list containing both, with type clearly indicated.
- [ ] Selecting an issue runs `gh issue view <number>` for that issue.
- [ ] Selecting a PR runs `gh pr view <number>` for that PR.
- [ ] Pressing Esc exits with no error message.
- [ ] Missing `gh` or `fzf` produces an actionable error message and a non-zero exit.
- [ ] Running outside a GitHub repo produces a clear error and a non-zero exit.
- [ ] An empty repo (no issues or PRs) prints a message and exits 0.
- [ ] The command is documented (usage comment or README/alias list, per repo convention).

## Open Questions

- Should closed and merged items be included by default, or only via a flag such as `-a`/`--all`?
- Should extra arguments pass through to `view` (e.g. `ghv --web`)?
- Should a preview pane be included by default?
- Where do existing helper commands live in this repo (shell functions, `bin/` scripts, or aliases)? The new command should follow that convention.
- Does the "view" in "associated 'view' command" mean `gh issue view`/`gh pr view`, or is there an existing `view` wrapper in the dotfiles to reuse?

## Notes

- Dependencies: `gh`, `fzf`. A `jq` dependency should be avoided where `gh --json` with `--jq`/`--template` can do the formatting.
- Suggested implementation: format each line as tab-separated `type<TAB>number<TAB>title...`, and have `fzf` return the full line, which is then parsed to choose the `view` subcommand.
