# feat(bootstrap): convert bootstrap.sh into an Ansible role

## Summary

Convert `bootstrap.sh` into an Ansible role (`roles/dotfiles/`) that replaces as much of it as possible. This is a holistic rewrite serving reliability/idempotency, maintainability, and multi-machine profiles.

A thin residual `bootstrap.sh` (~30 lines) survives only to solve the chicken-and-egg of installing brew and ansible, then execs the playbook.

Of the session-daemon `eval`s, `gpg-agent --daemon` and `mise activate` stay in shell startup (`bash_profile`/`zshrc`), where they already run on every login. `ssh-agent` is **not** wired into shell startup today (follow-up #155). On macOS the keychain handles SSH auth. On Linux, passphraseless keys work without an agent.

## Motivation / Context

The original idea: "turn this dotfiles repo into an ansible role that replaces as much of the bootstrap.sh as possible."

`bootstrap.sh` is a 485-line bash script covering:

- symlinks and directory creation
- terminfo
- GPG/SSH key generation and agent setup
- TPM plugin install
- OS prereqs (apt/pacman)
- rustup and mise
- a large Homebrew formulae/cask list
- vim-plug and nvim plugins
- pynvim, the neovim gem, and gopls
- zoxide migration
- beads hydration

Drivers:

- Fix the idempotency bugs: #41 (`rm -rf` with no backup), #45 (non-idempotent macOS SSH config), and #48 (duplication).
- Replace 485 lines of bash with declarative YAML.
- Enable per-machine customization (overlaps with #152).

## Requirements

### Layout & invocation

- **Role-in-repo + local playbook.** Standard `roles/dotfiles/{tasks,defaults,handlers,files,templates,vars,meta}/` in this repo.
- Top-level `playbook.yml` targets `localhost` with `connection: local`, configured via `ansible.cfg` so no inventory file is needed for the common case (`ansible-playbook playbook.yml`).
- Dotfiles move into `roles/dotfiles/files/` and are symlinked into `$HOME` via `ansible.builtin.file` (`state: link`, `force: yes`). This replaces the `rm -f` + `ln -sf` pattern and **fixes #41**. Backup strategy: `force` overwrites non-links, and pre-existing regular files are first backed up via a `copy` task with a remote suffix before linking.
- Reusable externally: `ansible-galaxy install git+https://github.com/tribou/dotfiles`.
- The checkout lives at `~/dev/dotfiles` (matches the hardcoded `DOTFILES` in `bash_profile`). The role symlinks from absolute `role_path`, so the checkout path is the single source of truth for link targets.

### Scope (aggressive: everything except session-daemon evals)

Ansible performs everything except the session-daemon `eval`s, which cannot mutate the parent shell from a subprocess.

- `gpg-agent --daemon` and `mise activate bash` come up via existing shell-startup wiring when the user opens a fresh login shell after the run.
- `ssh-agent` is out of scope (follow-up #155). The role's `ssh` task does replicate the macOS `ssh-add --apple-use-keychain` pre-load, which is a real persistent effect. The dead Linux inline `ssh-agent` subprocess eval is dropped as cleanup.

### Task structure (tagged, by concern)

Tasks are split into focused files under `roles/dotfiles/tasks/`, each tagged:

| Tag | File | Covers (current bootstrap.sh lines) |

| `links` | `links.yml` | All symlinked dotfiles: `.bash_profile`, `.vimrc`←`init.vim`, `.gitconfig`, `.zshrc`, `.tmux.conf`←`tmux/tmux-conf`, mise default packages, `.gnupg/gpg-agent.conf`, nvim `init.vim` + `coc-settings.json`, alacritty, mise config, helper scripts (52-65, 69-74, 89, 105, 110, 115, 119, 123-124) |
| `terminfo` | `terminfo.yml` | `tic -x tmux/*.terminfo` via `command` with `changed_when` (83-84) |
| `gpg` | `gpg.yml` | Perms (`0600` files, `0700` dir), `chown`, agent *config* only, no daemon restart (90-92) |
| `ssh` | `ssh.yml` | Keypair via `community.crypto.openssh_keypair` (rsa 4096 + ed25519, no passphrase); macOS `~/.ssh/config` via `blockinfile` with marker, **fixes #45** (136-159) |
| `tpm` | `tpm.yml` | Clone tpm, install plugins via detached-session workaround (175-188) |
| `prereqs` | `prereqs.yml` | Linux apt/pacman full developer list: `build-essential`, `zlib1g-dev`, `xdg-utils`, `bash-completion`; `apt update_cache=yes` always (full `apt upgrade` gated to `dotfiles_state == 'latest'` in `upgrade.yml`) (203-211) |

| `mise` | `mise.yml` | Install/self-update mise, `mise install node go bun ruby` (precompiled fallback preserved), `corepack enable` (226-275) |

| `brew` | `brew.yml` | Install Homebrew if missing; `homebrew_tap`; core formulae from vars; tmux `--HEAD` + `homebrew` pinned state (#138 workaround preserved); Linux `gcc`; `git-delta` reinstall-on-mismatch guard (292-384) |
| `brew_casks` | `brew_casks.yml` | macOS-only formulae + casks; `brew bundle --global` when `~/.Brewfile` is present (#152 hook) (387-411) |
| `nvim` | `nvim.yml` | vim-plug install + `nvim --headless +PlugInstall --sync +qall`; `pip3 install --user pynvim`; `gem install neovim`; `go install gopls` (414-428, 442-454) |
| `zoxide` | `zoxide.yml` | Legacy `~/.z` → zoxide migration, idempotent (431-439) |
| `beads` | `beads.yml` | `bd bootstrap` / `bd dolt remote add`, pure commands (461-480) |
| `upgrade` | `upgrade.yml` | **Only included when `dotfiles_state == 'latest'`.** See "Package updates" below. Tagged `upgrade` so `--tags upgrade` runs only these. |

`tasks/main.yml` includes them in dependency order (prereqs → rust → mise → brew → nvim, etc.).

### Variables (`defaults/main.yml`)

- `dotfiles_state`: `present` (default; install-if-missing, fast/safe) or `latest` (also upgrade everything; triggers `tasks/upgrade.yml`).
- `dotfiles_brew_core`: always-installed core formulae, taken from the current `brew install` block.
- `dotfiles_brew_linux` (`gcc`) and `dotfiles_brew_macos`: formulae/cask lists.
- `dotfiles_mise_tools`: defaults `{node, go, bun, ruby}`.
- `dotfiles_npm_globals`: `{neovim, eslint_d, editorconfig}`.
- `dotfiles_ssh_key_email`: `"tribou@users.noreply.github.com"`.
- `dotfiles_home`: `{{ ansible_env.HOME }}` (overridable, enables root-in-container testing).

The core brew list lives in `defaults/` (not `vars/`) so it stays overridable.

### Profiles & #152 (orthogonal, not subsumed)

Core lists are role vars, overridable via `--extra-vars` or inventory. Optional tooling stays on #152's file-drop mechanism:

- `~/.Brewfile`, consumed by `brew bundle --global`
- `~/.config/mise/conf.d/*.toml`, auto-merged by `mise install`

The role runs `mise install` and `brew bundle --global` (when files are present) and is profile-dumb beyond core. **#152 ships as-is and remains open.**

### Platform handling

Standard Ansible conditionals, no custom fact-gathering:

- macOS: `when: ansible_system == 'Darwin'`
- Debian/Ubuntu: `when: ansible_os_family == 'Debian'`
- Arch: `when: ansible_os_family == 'Archlinux'`

### Secrets & keys

- SSH keys: `community.crypto.openssh_keypair` (generates only if absent; rsa 4096 + ed25519; no passphrase, matching current behavior).
- macOS `~/.ssh/config`: `blockinfile` with `# BEGIN dotfiles` / `# END dotfiles` markers (fixes #45).
- GPG signing key: manual, out of scope (README already documents it).
- `~/.ssh/api_keys`: role ignores entirely. Missing-env-var warnings stay in `bash_profile` (e.g. `GIT_SIGNING_KEY` warns if unset).
- Vault: documented as a future option, not built now.

### Residual `bootstrap.sh` (~30 lines)

Responsibilities:

1. **Self-locate / self-clone.** If invoked via `curl|bash` (not inside the repo), install minimal `curl git ca-certificates`, `git clone` to `~/dev/dotfiles`, and re-exec itself there.
2. **Linux brew-bootstrap prereqs** (chicken-and-egg): `curl git build-essential ca-certificates` (apt) or `curl git base-devel` (pacman). Brew's installer needs a C toolchain on Linux. macOS needs nothing extra.
3. **Install brew (if missing) → `brew install ansible` → `exec ansible-playbook playbook.yml`.**

On success, print: `open a new login shell (or: exec $SHELL -l) so mise/gpg-agent/brew/cargo PATH take effect`. This restart requirement is not new; the current script has the same one, since its inline `eval`s also die with the subprocess.

**Prereq ownership split** (avoids #48-style duplication while respecting chicken-and-egg):

- `bootstrap.sh` owns the minimal set brew needs: `curl git build-essential ca-certificates`.
- The role's `prereqs` task owns the full developer apt list (adds `zlib1g-dev xdg-utils bash-completion`) and runs `apt update_cache=yes` on every run.
- The overlap on `build-essential` is intentional and documented; both are idempotent no-ops after first run.

### New-machine runbook

- **curl one-liner:** `bash -c "$(curl -fsSL https://raw.githubusercontent.com/tribou/dotfiles/HEAD/bootstrap.sh)"` (self-clones to `~/dev/dotfiles`).
- **Explicit:** `mkdir -p ~/dev && git clone https://github.com/tribou/dotfiles.git ~/dev/dotfiles && cd ~/dev/dotfiles && ./bootstrap.sh`.
- **Ansible already present** (CI / containers / re-runs): `cd ~/dev/dotfiles && ansible-playbook playbook.yml`, or once bootstrapped, `just install` (supports `--tags ssh,links` subsets and `--check --diff`).

### Package updates (install vs upgrade)

The current `bootstrap.sh` only truly upgrades apt/pacman on re-run. Homebrew formulae, casks, mise tools, npm globals, nvim plugins, TPM, and rustup are install-only and silently skipped on re-run. The new structure makes updates explicit via a single variable:

- **`dotfiles_state: present`** (default): every package module uses `state: present`. Re-runs are fast and never trigger a surprise upgrade.
- **`dotfiles_state: latest`**: additionally includes `tasks/upgrade.yml` (tagged `upgrade`), which covers:
  - Module-expressible upgrades: `apt upgrade=yes`, `pacman -Syu`, `homebrew upgrade_all`, `homebrew_cask upgrade`, `pip`/`gem` `state=latest`, `mise upgrade --yes`.
  - Command-based upgrades: `rustup self-update && rustup update`, `nvim +PlugUpdate --sync`, TPM `update_plugins` (detached-session workaround), `npm install -g <pkgs>`, `claude upgrade`, `opencode upgrade`, `bd dolt pull`.

Run modes:

- `./bootstrap.sh` (or curl one-liner): first-time entry on a machine with no `just`/`ansible`.
- `just install`: re-run/repair on an already-bootstrapped machine (`ansible-playbook playbook.yml`, default `present`).
- `just upgrade`: wrapper for `ansible-playbook playbook.yml -e dotfiles_state=latest --tags upgrade`.
- `--check --diff` previews either mode.

### Justfile targets (new)

- **`just install`** → `ansible-playbook playbook.yml`. `just`/`ansible` exist only after the first `./bootstrap.sh`, so first-time entry remains `./bootstrap.sh` or the curl one-liner.
- **`just upgrade`** → `ansible-playbook playbook.yml -e dotfiles_state=latest --tags upgrade`.
- Both forward extra args to `ansible-playbook` (e.g. `just install --check --diff`, `just upgrade --tags brew`).
- Ship and document a sample scheduled `just upgrade` wrapper.

### Testing

- **Molecule** (`roles/dotfiles/molecule/`): role-dev loop. `molecule converge` for fast iteration; the `idempotence` phase reruns converge and asserts `changed=0` (directly serves driver #1). Verifier reuses `goss.yaml`. `molecule create` uses a matching Ubuntu image.
- **Docker + goss + bats**: retained as the CI integration gate (`just test`) and the `just dev` interactive entrypoint. `Dockerfile` swaps `bootstrap.sh` for `ansible-playbook -i localhost, playbook.yml`. The `goss.yaml` contract and `tests/integration/*.bats` are untouched.
- Goal: `--check`/`--diff` cleanliness across all tasks.

### CI impact

- `Dockerfile`: replace the `bootstrap.sh` invocation with `ansible-playbook` (install ansible-core in the image, run against localhost). Layer caching still applies.
- `docker-compose.yml` / `just test`: unchanged contract, same goss+bats verification.
- Molecule: optional in CI initially; can be gated later as a separate job.

## Non-goals

- Replacing the session-daemon `eval`s (impossible from a subprocess).
- Generating the GPG signing key (interactive, manual).
- Managing `~/.ssh/api_keys` or adopting Vault in this pass.
- Subsuming #152 (file-drop opt-in stays as #152 specifies).
- Changing the `lib/` shell libraries or the bats unit tests (they test shell functions, not bootstrap).
- Removing `bootstrap.sh` entirely (it stays as the thin brew+ansible bootstrapper).
