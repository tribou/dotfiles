# Split lib/commands.sh monolith into focused modules

## Summary

`lib/commands.sh` is 1,384 lines containing 61 functions and 135 aliases across unrelated domains (git, npm, docker, tmux, AWS, DigitalOcean, terraform, SSH, general shell utilities). It cannot be tested in isolation, is hard to review, and causes avoidable merge conflicts. Split it into focused domain modules per the standard in #153 (boundaries, size, naming, load order). This is the first concrete application of that standard.

## Prerequisite (land first, with its own test)

Make `lib/index.sh` source underscore-prefixed files (`_*.sh`) **first and explicitly**, before the remaining modules.

Reason: under `en_US.UTF-8`, the current `ls`/glob ordering places `_shared.sh` 10th of 11, not first. Any split that introduces a source-time dependency on `_shared.sh` could break silently.

This change and its test must merge before any module is split out.

## Scope

Split `lib/commands.sh` into the following modules. The split is a suggestion; boundaries must conform to #153.

| File | Contents |
|---|---|
| `lib/git.sh` | git aliases and functions (co, merge, branch management, commit helpers) |
| `lib/npm.sh` | npm/node detection and helpers |
| `lib/docker.sh` | docker/container helpers |
| `lib/tmux.sh` | tmux session and window management helpers (large, ~71 keyword hits) |
| `lib/cloud.sh` | AWS, DigitalOcean, terraform, SSH cloud helpers |
| `lib/repo.sh` | repo scaffolding: the `.gitignore` generator (~L712–745) and `mkrepo` |
| `lib/agent.sh` | agent state: the Claude keep-alive loop (~L375–388) and related helpers |
| `lib/commands.sh` | only what fits none of the above (general shell utilities) |

Constraints:

- **`cloud.sh` stays one file** until it nears the ~300-line cap (per #153's boundary rule), then splits by tool. Do not pre-split the small terraform/ssh pieces.
- **`repo.sh` must not fall into the general bucket.** The `.gitignore` generator and `mkrepo` belong there explicitly.
- `lib/index.sh` already sources `lib/*.sh` dynamically (glob, excluding `index.sh`), so new files are picked up automatically once the prerequisite ordering fix is in.
- Do **not** change function signatures or alias names. This is a pure file reorganization.

## Acceptance criteria

- [ ] Prerequisite ordering fix and its test are merged before the split begins.
- [ ] `just test-unit` passes.
- [ ] `just test` passes.
- [ ] In a fresh shell session, all pre-existing aliases and functions still work (the 61 functions and 135 aliases are all still defined, with unchanged names and signatures).
- [ ] `wc -l` on every `lib/*.sh` file is at or under ~300 lines (soft cap per #153).
- [ ] `_shared.sh` is sourced before every non-underscore module.
- [ ] `bashcheck` (the project linter; not `bash -n`) passes on each new and modified file.

## Notes

- See `lib/index.sh` for how sourcing works.
- Line references (~L375–388, ~L712–745) are approximate and refer to the current `lib/commands.sh`; re-verify before moving code.
- The remaining `lib/commands.sh` should be small and contain only general shell utilities.
