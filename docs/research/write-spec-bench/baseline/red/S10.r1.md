# refactor(packages): make mise the primary package manager

## Summary

Make mise the primary package manager for runtimes, language-level global packages, and the formulae currently managed by Homebrew.

- Use mise tool backends for version-switched CLIs.
- Use mise's built-in `brew:` manager for packages that still need Homebrew formula artifacts.
- Keep the existing Homebrew cask flow.

## Motivation / Context

- Default Node, Python, and Ruby packages are managed separately from `mise-config.toml`.
- Homebrew owns a broader package set than mise.
- Homebrew bootstraps Ansible before mise is installed, so the bootstrap order is inverted relative to the goal.
- Mise deprecates default Python package files, with warnings scheduled for 2026.11.0 and removal for 2027.11.0. That is a deadline for moving package behavior into TOML.
- Mise 2026.7.5 already exposes `mise bootstrap packages`.
- Current mise documentation describes a built-in `brew:` manager that installs Homebrew formulae into the canonical prefix without requiring Homebrew.
- Mise also documents `brew-cask:`, with narrower platform and lifecycle coverage. This is why casks stay on the existing flow.
- Making mise the orchestration boundary for residual Homebrew artifacts would remove the separate Ansible Homebrew modules and Brewfile flows.

Consolidating ownership and bootstrap under mise should:

- reduce overlap between managers
- make configured versions explicit
- establish one primary package manager going forward

## Goals

- `mise-config.toml` is the single source of truth for runtimes, language-level global packages, and CLI tools.
- Default package files for Node, Python, and Ruby are removed, and their contents are expressed in TOML.
- Formulae with no suitable mise backend are installed through `brew:` entries, not Ansible Homebrew modules or Brewfiles.
- Bootstrap installs mise first, then uses it to install everything else, including Ansible.
- The Homebrew cask flow continues to work unchanged.

## Non-goals

- Migrating casks to `brew-cask:`.
- Removing Homebrew from machines that need it for casks.
- Changing which tools are installed, except where a backend change requires it.

## Proposed Approach

1. **Inventory.** List every package currently owned by:
   - default Node, Python, and Ruby package files
   - Homebrew formulae (Brewfile and Ansible modules)
   - casks

   Classify each formula by its destination:
   - a mise tool backend
   - a `brew:` entry
   - stays on Homebrew

2. **Language packages.** Move default package contents into `mise-config.toml` using appropriate backends. Delete the default package files.

3. **Formulae.** Move version-switched CLIs to tool backends, and move the remainder to `brew:` entries.

4. **Bootstrap.** Reorder so mise is installed first and Ansible is installed through mise. Remove Homebrew as a prerequisite for non-cask packages.

5. **Cleanup.** Remove Ansible Homebrew formula tasks and Brewfile formula entries. Keep the cask flow intact.

6. **Docs.** Update the README and any bootstrap docs to describe mise as the primary package manager.

## Acceptance Criteria

- [ ] An inventory document or PR description maps every existing package to its new owner.
- [ ] No default package files for Node, Python, or Ruby remain, and `mise` emits no deprecation warnings for them.
- [ ] All formula-based packages are declared in `mise-config.toml` or the `brew:` configuration, and none remain in Brewfiles or Ansible Homebrew formula tasks.
- [ ] A fresh-machine bootstrap installs mise first and then Ansible through mise, with no Homebrew dependency for non-cask packages.
- [ ] The cask flow works as before.
- [ ] `mise bootstrap packages` (or the equivalent invocation) is idempotent on a second run.
- [ ] Verified on every supported platform (at least macOS and Linux), with any platform gaps documented.
- [ ] Docs are updated.

## Risks / Open Questions

- **Platform coverage.** `brew:` and `brew-cask:` may have platform-specific limits. Confirm which formulae work on each supported OS before removing the Homebrew fallback.
- **Version pinning.** Decide whether tools are pinned to exact versions or tracked as `latest`. The goal of explicit versions suggests pinning.
- **Formula parity.** Formulae with post-install steps, services, or linked-keg behavior may not behave the same under `brew:`.
- **Mise version floor.** Specify the minimum mise version (at least 2026.7.5) and how bootstrap guarantees it.
- **Migration path.** Decide how existing machines move from Homebrew-owned to mise-owned installs without duplicate binaries on `PATH`.
- **Deadline.** Python default package file warnings begin in 2026.11.0, so the language-package portion should land first. It can ship independently of the formula migration.

## Suggested Split

1. Move language default packages into TOML (time-sensitive).
2. Move formulae to mise backends and `brew:`.
3. Invert bootstrap order and remove the Ansible and Brewfile formula flows.
