# feat(shell): add `qq` one-off AI question command

## Summary

Add a `qq` shell command that sends a single, context-free question to the configured AI backend (`opencode` / `claude` / `agy`) and prints the answer. Bare `qq` opens a `qq> ` prompt. `qq some question` passes the typed text verbatim, with no shell escaping needed. Backend and model settings are shared with `commit` under renamed `DOTFILES_AI_*` env vars, and the shared helpers move into a new `lib/ai.sh`.

## Motivation / Context

The user wants a quick way to ask the configured AI harness a one-off question from the terminal, using the same model settings as `commit`. The `c` alias passes extra args to commit with little friction, so the same ergonomics are wanted here. Bash mangles special characters (`?`, `*`, `>`, `$VAR`, quotes) before a function sees its args, so detecting and rejecting them is not feasible. Instead, `qq` reads the raw typed line from history.

Existing overlap: `commit` in `lib/git.sh` already resolves backend, model and timeout through:
- `_dotfiles_commit_backend` (`DOTFILES_COMMIT_BACKEND`, default `opencode`; also `claude`, `agy`)
- `_dotfiles_commit_model` (`DOTFILES_COMMIT_MODEL`, per-backend defaults)
- `_dotfiles_commit_timeout` (`DOTFILES_COMMIT_TIMEOUT`, default 15s)
- `_dotfiles_spinner_wait`

`c` joins args with `"$*"`.

## Requirements

### Shared AI settings (renamed)
- `DOTFILES_COMMIT_BACKEND` → `DOTFILES_AI_BACKEND` (same values: `opencode` default, `claude`, `agy`).
- `DOTFILES_COMMIT_MODEL` → `DOTFILES_AI_MODEL` (same per-backend defaults when unset).
- `qq` and `commit` resolve backend and model through the same shared helpers, so one setting drives both.

### Deprecated-name fallback
- If `DOTFILES_AI_BACKEND` / `DOTFILES_AI_MODEL` is unset but the old `DOTFILES_COMMIT_BACKEND` / `DOTFILES_COMMIT_MODEL` is set, use the old value and print a one-line deprecation warning naming the new variable to **stderr** (never stdout).
- When the new name is set, it wins and no warning is printed.

### Per-command timeouts
- `qq` has its own `DOTFILES_QQ_TIMEOUT`, default **60s**.
- Parsing mirrors commit's parser: empty or non-numeric falls back to the default; `0` means no timeout (wait until the backend finishes; Ctrl-C still cancels).
- `commit` keeps `DOTFILES_COMMIT_TIMEOUT` (default 15s). Timeouts are per-command, not shared.

### Structure
- New `lib/ai.sh` holds the shared helpers, renamed to `_dotfiles_ai_*`:
  - `_dotfiles_ai_backend` / `_dotfiles_ai_model` (read `DOTFILES_AI_*` with the deprecated-name fallback and warning)
  - `_dotfiles_ai_spinner_wait` (was `_dotfiles_spinner_wait`)
  - a small timeout parser parameterized by variable name and default (commit uses 15, qq uses 60)
  - `_dotfiles_qq` and the `qq` alias
- `lib/git.sh`: `commit` and `_dotfiles_commit_generate_message` call the `_dotfiles_ai_*` helpers. Commit-specific pieces (prompt, sanitize, `DOTFILES_COMMIT_TIMEOUT`) stay in `git.sh`.
- `lib/index.sh`: no change (it already sources every `lib/*.sh`).

### `commit` subcommands
- `commit backend X` now exports `DOTFILES_AI_BACKEND`, so it also switches `qq`.
- `commit status` also shows the `qq` timeout alongside the existing backend/model/timeout/available lines.

### No `qq` subcommands
Any input, e.g. `qq status of my PR`, is always treated as a question.

### Prompt wrapper
`qq` prepends a short fixed instruction to the question, e.g. "Answer concisely for display in a terminal. Prefer short answers; use code blocks for commands." The wrapper is fixed, with no env override.

### Context-free
- Pure Q&A with no repo or file access.
- The backend is invoked outside the user's cwd (e.g. from a temporary empty directory) and, where the CLI supports it, with tools disabled.
- Exact per-backend flags are an implementation detail to verify against each CLI's current docs.
- The user's shell cwd is unchanged after `qq` returns.

### Runtime flow
1. Obtain the question. Interactive shells use the raw history line; non-interactive calls use `"$*"`. If the result is empty, fall through to the `qq> ` prompt.
2. Resolve backend and model via `_dotfiles_ai_*`.
3. Launch the backend in the background from a temporary empty directory with wrapper + question.
4. Show the spinner on **stderr** (e.g. `Asking Opencode...`).
5. Print the answer to **stdout** as-is: multi-line, code blocks intact. Unlike `commit`, it is not truncated to one line; only leading/trailing blank lines are trimmed.
6. Clean up the temp dir and output file.

### Stdout is answer-only
Everything except the answer (spinner, warnings, errors) goes to stderr. With the raw-history args form, a trailing `| cmd` on the `qq` line is part of the question, so piping the answer works only with bare `qq` or non-interactive calls.

### Errors
There is no manual fallback (unlike `commit`, which falls back to `c`). Every error prints one line to stderr and exits non-zero:

| Case | Message (stderr) | Exit |
|---|---|---|
| Empty input / Ctrl-D / Ctrl-C at `qq>` | (none) | 1 (130 on Ctrl-C) |
| Leading-space guard trips | `qq: question not in history (leading space?); run bare qq instead` | 1 |
| Backend CLI not installed | `qq: <backend> not found` | 1 |
| Ctrl-C while waiting | `qq canceled` | 130 |
| Timeout | `qq: <backend> timed out after <N>s` | 124 |
| Backend fails / empty output | `qq: <backend> returned no answer` | 1 |

### No-arg input prompt
Bare `qq` shows a `qq> ` prompt and reads one line with `read -e -r` (readline editing; the text is not parsed by the shell). Enter submits. Empty input, Ctrl-D, or Ctrl-C exits without calling the backend.

### Args as prompt via raw history line
- Define `alias qq='_dotfiles_qq #'`. The trailing `#` makes bash treat the rest of the line as a comment, so it is not parsed, expanded, globbed, or redirected.
- `_dotfiles_qq` reads the current command from `history 1` (with `HISTTIMEFORMAT` neutralized), strips the history number and everything up to and including the `qq` invocation, and uses the remainder verbatim as the question.
- `? * $VAR > < ; & | ' "` all pass through literally. A throwaway spike verified `what's up`, `a > b means what`, `$HOME`, `*`, `?`, `;` and double quotes arriving verbatim, with no redirect file created.
- If the remainder is empty (bare `qq`), fall through to the `qq> ` prompt.

### Leading-space guard
`bash_profile` sets `HISTCONTROL=ignorespace`, so a command typed with a leading space is not recorded and `history 1` returns the *previous* entry. The spike showed this silently re-sending an older question. `_dotfiles_qq` must detect that the current command was not recorded, exit non-zero with the error above, and never send a stale history entry.

### Non-interactive fallback
In scripts and non-interactive shells (aliases and history inactive), `_dotfiles_qq` is called directly with real args and uses `"$*"`.

### Known limitations (documented, not worked around)
- **`!word`:** history expansion runs before the comment is recognized, so `qq is !important bad` fails with bash's own `event not found` and nothing is sent. This is visible, not silent.
- **Line continuation:** a trailing `\` is not supported in the args form (only the first physical line is recorded). Use bare `qq` for such input.

### Docs
Update `docs/DEVELOPMENT.md` with:
- the renamed vars and the deprecation fallback
- `DOTFILES_QQ_TIMEOUT`
- a short `qq` usage note: args form vs. bare `qq`, the `!word` and leading-space limits, and piping only with bare `qq`

## Non-goals
- Multi-turn chat / follow-up questions
- Repo-aware answers (file reads, tools)
- Streaming output
- Markdown rendering
- Reading the question from piped stdin
- `qq` subcommands
- An env override for the wrapper prompt
- Working around `!word` history expansion

## Testing

Bats tests, written TDD-first, following the existing pattern (source libs in `bash -c`, stub `claude` / `opencode` / `agy` as shell functions).

- **Update existing tests** for the renamed vars/helpers: `tests/commit_backend.bats`, `tests/commit_command.bats`, `tests/commit_generate_message.bats`, `tests/spinner_wait.bats`.
- **Deprecation fallback:**
  - only the old name set → its value is used and a warning is printed on stderr
  - new name set → it wins, no warning
  - the warning never appears on stdout
- **New `tests/qq_command.bats`:**
  - Non-interactive args form uses `"$*"`.
  - Raw-history path, exercised under `bash -i` with an rcfile (as in the spike): `?`, `*`, `$HOME`, `>`, `;`, `'` arrive verbatim, and no redirect file is created.
  - Leading-space guard errors and does **not** send the previous history entry.
  - Bare `qq` with empty input exits 1 without calling the backend.
  - The terminal wrapper text is included in the prompt sent to the backend.
  - The backend runs in a directory other than `$PWD`, and the caller's cwd is unchanged afterwards.
  - Multi-line answers are preserved; leading/trailing blank lines are trimmed.
  - Error rows: backend not found → exit 1; timeout (short `DOTFILES_QQ_TIMEOUT`) → exit 124; empty answer → exit 1.
  - stdout contains only the answer.
- **`tests/lib_modules.bats`:** add a `type qq` check for `ai.sh`.
- **Quality gates:** `bashcheck` on changed lib files, then `just test-unit` and `just test`.

## Acceptance criteria

- [ ] `lib/ai.sh` exists with the `_dotfiles_ai_*` helpers and `qq`; `lib/git.sh` uses them.
- [ ] `qq <question>` passes special characters verbatim in interactive shells; bare `qq` prompts with `qq> `.
- [ ] The leading-space case errors instead of sending stale history.
- [ ] The backend runs context-free from a temp dir; the caller's cwd is unchanged.
- [ ] Stdout contains only the answer; all errors follow the table above.
