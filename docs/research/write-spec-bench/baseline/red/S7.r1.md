# fix(shell): histgrep clipboard copy fails over SSH without a display

## Summary
`histgrep` (alias `hg`) fails with `Error: Can't open display: (null)` over SSH because the shared clipboard helpers select `xclip` whenever it is installed, without checking for an X display. Make every clipboard write path display-aware and fall back to OSC 52 so the selected command lands in the user's local clipboard.

## Motivation / Context
Running `histgrep` over SSH on a Linux server fails after selecting a result:

```
> hg fei
fei
Error: Can't open display: (null)
```

Outside tmux, `histgrep` (`lib/commands.sh`) echoes the result and pipes it into `copy_to_clipboard`. `_dotfiles_clipboard_write_cmd` picks `xclip` whenever it is installed, without checking that `DISPLAY` is set. In a headless SSH session `xclip` errors. The read side (`_dotfiles_clipboard_read_cmd`) has the same gap, as does `scripts/tmux-copy.sh`.

Related precedent: #197 switched nvim to an OSC 52 clipboard provider for headless/SSH panes.

## Requirements
- Over SSH with no X display, `histgrep` copies the selected command to the user's **local** clipboard via OSC 52 instead of calling `xclip` and erroring.
- The shared clipboard write helper in `lib/commands.sh` (`_dotfiles_clipboard_write_cmd` / `copy_to_clipboard`) is display-aware: it does not select `xclip` when `DISPLAY` is unset, and falls back to OSC 52.
- The shared clipboard read helper (`_dotfiles_clipboard_read_cmd`) is display-aware: it does not select `xclip` when `DISPLAY` is unset, and returns empty (no OSC 52 read).
- `scripts/tmux-copy.sh` (tmux right-click menu Copy) gets the same display-aware handling, falling back to OSC 52 through tmux. It stays in scope even though it is never invoked over SSH today (the right-click menu is not sourced over SSH); the goal is consistent display-aware behavior across every clipboard write path.
- No path prints an error when no clipboard mechanism is reachable; the fallback fails silently.

## Non-goals
- No `wl-copy`/`wl-paste` (native Wayland) support.
- No OSC 52 clipboard *read*.
- No changes to the tmux mouse `copy-pipe copy_to_clipboard` bindings or `scripts/tmux-paste.sh`.
- No change to `histgrep` itself.

## Design
- **Display check:** `xclip` is used only when `DISPLAY` is set. `xclip` is X11-only, so `WAYLAND_DISPLAY` alone does not qualify.
- **Write order (`lib/commands.sh`):** `pbcopy` → `xclip -selection clipboard` if `DISPLAY` is set → new `_dotfiles_osc52_copy`.
- **`_dotfiles_osc52_copy`:**
  - Reads stdin and base64-encodes it with newlines stripped (portable across GNU and BSD `base64`).
  - Inside tmux (`$TMUX` set), pipes the text to `tmux load-buffer -w -` so tmux emits OSC 52 itself. `set-clipboard on` is already set in `tmux/tmux-conf`; `-w` requires tmux 3.2+, and the local tmux is 3.7b.
  - Outside tmux, writes `\e]52;c;<b64>\a` to `/dev/tty`, with the output target overridable for tests.
  - If `/dev/tty` is not writable, it no-ops silently.
- **Read order:** `pbpaste` → `xclip -o -sel clipboard` if `DISPLAY` is set → nothing. No OSC 52 read: terminal query round-trips are slow and unreliable (see #197).
- **`scripts/tmux-copy.sh`:** `pbcopy` → `xclip -selection clipboard` if `DISPLAY` is set → `tmux load-buffer -w -` with the current buffer.
- **Unchanged:** `histgrep`; its tmux branch (`send-keys`) never touches the clipboard.

## Testing
TDD per repo policy: write failing bats tests first.
- `tests/clipboard.bats`:
  - `xclip` present + `DISPLAY` unset → write helper selects OSC 52, not `xclip`.
  - `xclip` present + `DISPLAY` set → still selects `xclip`.
  - Read helper returns empty when `xclip` is present but `DISPLAY` is unset.
- OSC 52 writer:
  - Outside tmux, emits `ESC ] 52 ; c ; <base64> BEL` to its output target.
  - Inside tmux (`TMUX` set, stub `tmux`), calls `tmux load-buffer -w -` with the text.
- `tests/tmux_copy.bats`: `xclip` present + `DISPLAY` unset → uses `tmux load-buffer -w -` instead of `xclip`.
- Quality gates: `just test-unit` and `just test`.
