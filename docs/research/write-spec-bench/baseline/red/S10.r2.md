# refactor(packages): make mise the primary package manager

## Summary

Make mise the primary package manager for runtimes, language-level global packages, and the formulae currently managed by Homebrew. Use mise tool backends for version-switched CLIs. Use mise's built-in `brew:` manager for packages that still need Homebrew formula artifacts. Keep the existing Homebrew cask flow.

## Motivation / Context

- Default Node, Python, and Ruby packages are managed separately from `mise-config.toml`.
- Homebrew owns a broader package set, and Ansible is bootstrapped through Homebrew before mise is installed.
- Mise deprecates default Python package files. Warnings begin in 2026.11.0 and removal is scheduled for 2027.11.0, so package behavior needs to move into TOML. The first warning release is close, so this is time-sensitive.
- Mise 2026.7.5 exposes `mise bootstrap packages`. Its documentation describes a built-in `brew:` manager that installs Homebrew formulae into the canonical prefix without requiring Homebrew. It also describes `brew-cask:`, which has narrower platform and lifecycle coverage.
- Consolidating ownership under mise should reduce overlap between tools, make configured versions explicit, and establish one primary package manager. It would also let mise orchestrate the residual Homebrew artifacts instead of separate Ansible Homebrew modules and Brewfile flows.

## Scope

1. **Language-level defaults into TOML.** Move default Node, Python, and Ruby global packages into `mise-config.toml`. Remove the separate default-package files.
2. **Formulae ownership.** Audit the current Homebrew formula set and assign each package to one of:
   - a mise tool backend (version-switched CLIs),
   - the mise `brew:` manager (formula artifacts with no suitable backend),
   - remaining on Homebrew, with a documented reason.
3. **Bootstrap.** Rework the bootstrap so mise is installed first, and Ansible comes from mise or `mise bootstrap packages` rather than Homebrew.
4. **Retire redundant flows.** Remove the Ansible Homebrew formula modules and Brewfile formula entries once their packages are covered by mise.
5. **Casks.** Keep the existing Homebrew cask flow unchanged. Evaluate `brew-cask:` but do not adopt it in this item.

## Out of scope

- Migrating casks to `brew-cask:`.
- Changing which tools or versions are installed, beyond making versions explicit.
- Changes to non-package dotfile management.

## Acceptance criteria

- [ ] No default Python, Node, or Ruby package files remain. Their contents are expressed in `mise-config.toml`.
- [ ] Every formula previously managed by Homebrew is recorded as migrated (backend or `brew:`) or explicitly retained on Homebrew with a reason.
- [ ] A fresh-machine bootstrap on each supported platform installs mise first and reaches a working Ansible without Homebrew formulae.
- [ ] Re-running the bootstrap on an already-provisioned machine is idempotent and makes no changes.
- [ ] Ansible Homebrew formula modules and Brewfile formula entries are removed. The cask flow still works.
- [ ] Configured tool versions are explicit and pinned in TOML.
- [ ] `mise` runs without default-package deprecation warnings on 2026.11.0 or later.
- [ ] Docs and README describe mise as the primary package manager and the bootstrap order.

## Risks / Considerations

- **Platform parity.** Confirm `brew:` behavior on every supported platform (macOS and Linux) before removing Homebrew formula management there.
- **Path and precedence conflicts.** Packages installed by both Homebrew and mise can shadow each other on `PATH`. Verify ordering during migration.
- **Bootstrap chicken-and-egg.** Installing mise itself needs a reliable non-Homebrew path.
- **Feature maturity.** `brew:` and `mise bootstrap packages` are newer. Pin a minimum mise version and verify behavior against it.
- **Cask coexistence.** Casks still depend on Homebrew, so Homebrew remains installed. Confirm the two cohabit without conflicting prefixes.

## Open questions

- Which platforms are in the support matrix for this repository?
- Should packages with both a mise backend and a `brew:` option prefer the backend by default?
- What minimum mise version should the bootstrap enforce?
- Should uninstalling migrated Homebrew formulae be automated or left as a manual cleanup step?
