# refactor(packages): make mise the primary package manager

## Summary

Make mise the primary package manager for runtimes, language-level global packages, and the formulae currently managed by Homebrew.

- Use mise tool backends for version-switched CLIs.
- Use mise's built-in `brew:` manager for packages that still need Homebrew formula artifacts.
- Keep the existing Homebrew cask flow unchanged.

## Motivation / Context

- Default Node, Python, and Ruby packages are managed separately from `mise-config.toml`.
- Homebrew owns a broader package set and bootstraps Ansible before mise is installed.
- Mise has deprecated default Python package files. Warnings are scheduled for 2026.11.0 and removal for 2027.11.0, so package behavior needs to move into TOML. The first warnings are about a month away.
- Mise 2026.7.5 already exposes `mise bootstrap packages`. Its documentation describes a built-in `brew:` manager that installs Homebrew formulae into the canonical prefix without requiring Homebrew.
- Mise also supports `brew-cask:`, but with narrower platform and lifecycle coverage. That is why casks stay on the current flow.
- Making mise the orchestration boundary removes overlap between tools, makes configured versions explicit, and gives the repo one primary package manager. It also lets us drop the separate Ansible Homebrew modules and Brewfile flows for residual formula artifacts.

## Proposed Change

1. **Runtimes and language globals:** Declare Node, Python, and Ruby runtimes and their default/global packages in `mise-config.toml`. Remove the separate default package files.
2. **Version-switched CLIs:** Move Homebrew-managed formulae that are CLIs onto the appropriate mise tool backend with pinned or explicit versions.
3. **Residual formulae:** Move formulae with no suitable mise backend to `brew:` entries, installed via `mise bootstrap packages`.
4. **Bootstrap:** Change the flow so mise is installed first and Ansible is provided through mise, instead of through Homebrew.
5. **Cleanup:** Remove the Ansible Homebrew formula modules and the Brewfile formula entries that are now redundant.
6. **Casks:** Leave the Homebrew cask flow unchanged.

## Out of Scope

- Migrating Homebrew casks to `brew-cask:`.
- Changing the set of packages installed. This is an ownership change, not a content change, except where a package must change backend.
- Upgrading mise beyond the minimum version needed for these features, unless required.

## Acceptance Criteria

- [ ] `mise-config.toml` declares Node, Python, and Ruby runtimes and all of their default/global packages. No default package files (such as the Python one) remain.
- [ ] Running mise on the minimum supported version produces no default-package-file deprecation warnings.
- [ ] Every formula previously installed via Homebrew is accounted for: it is installed via a mise backend, via `brew:`, or explicitly documented as retained and why.
- [ ] A fresh-machine bootstrap installs mise first, then Ansible and the remaining packages through mise, without requiring Homebrew for formulae.
- [ ] Homebrew is still installed or used only for casks, and the cask flow works as before.
- [ ] Redundant Ansible Homebrew formula modules and Brewfile formula entries are removed.
- [ ] Re-running the bootstrap on an already provisioned machine is idempotent and makes no unexpected changes.
- [ ] The minimum required mise version (at least 2026.7.5) is documented and enforced or checked.
- [ ] README/docs describe mise as the primary package manager and the cask exception.

## Risks / Open Questions

- **Platform coverage:** Which platforms does this repo target (macOS, Linux, or both)? The `brew:` manager and `brew-cask:` have platform limits that need to be checked against each target. This work item was written on Linux, so Linux behavior should be verified explicitly.
- **Version pinning policy:** Pin exact versions, or use ranges or `latest`, for migrated CLIs?
- **Backend selection:** Some formulae may lack a mise registry entry or a suitable backend (aqua, ubi, github, and so on). Each needs a per-package decision, ideally recorded in a migration table.
- **Bootstrap ordering:** Confirm that `mise bootstrap packages` can install Ansible and the other tools needed before Ansible runs, without a circular dependency.
- **Coexistence with an existing Homebrew install:** Confirm how `brew:` installs into the canonical prefix interact with a machine that already has Homebrew. This affects the migration path for existing machines, including whether to uninstall formulae from Homebrew afterwards.
- **Stability:** Confirm that `mise bootstrap packages` and the `brew:` manager are stable enough to be the primary mechanism, and note any experimental flags required.

## Suggested Verification

- Dry-run the bootstrap in a clean container or VM with no Homebrew installed.
- Run it on an existing machine with Homebrew formulae present.
- Run `mise doctor` and confirm that there are no deprecation warnings.
- Diff the installed package inventory before and after the migration.
