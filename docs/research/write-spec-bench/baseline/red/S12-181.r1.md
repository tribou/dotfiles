# feat(skills): agent usage ledger and GitHub audit comment

## Summary

Turn the normalized usage records from #180 into a durable audit trail on GitHub. This issue delivers three pieces:

- A **ledger**: one record per session per workflow stage, holding per-model breakdowns.
- A **rendered comment body**: a markdown table with a separate row for each model used, above a collapsed JSON block.
- An **upsert** that creates or updates a single dedicated audit comment on an issue or PR.

Part 2 of 3, split out of the original combined spec:

- **#180**: probe core + harness adapters (dependency)
- **#181 (this issue)**: ledger, rendering, and the GitHub audit comment
- **#182**: the shared `agent-usage-audit` skill and wiring of the three workflow skills

**Depends on #180.** This issue consumes the normalized record shape defined there.

## Motivation / Context

The probe measures; this layer makes the measurement durable and readable where the work already lives. Both purposes of the original spec depend on it:

- **Cost tracking** needs rows to accumulate across sittings and stages.
- **Provenance** needs rows to survive as an auditable record next to the issue or PR they describe.

## Design

### Audit placement

Use a **dedicated audit comment**: one `🤖 Agent usage` comment per issue or PR. It is found and updated **by marker content only** (`<!-- BEGIN AGENT USAGE -->` / `<!-- END AGENT USAGE -->`), never by comment position and never with `--edit-last`.

This layer never touches spec bodies or PR descriptions. That keeps the squash-merge commit prefill clean (the PR description doubles as the squash message in this repo's workflow). It also poses zero risk to the plan-marker gating that `issue-to-plan` and `plan-to-implementation` depend on, because the plan comment is a different comment with different markers.

Prior art: [pr-cost](https://github.com/jabertuhin/pr-cost) embeds cost blocks in PR descriptions, which is exactly the pollution this repo avoids.

### Attribution model

**Per-session ledger rows.** Each skill run (per sitting) contributes one record keyed by `(session_id, stage)`. A record holds: session id, stage, harness, models, model breakdowns, tokens, source.

- Re-running a stage within one sitting refreshes that record in place.
- A new sitting adds a record.
- Multi-sitting flows are therefore counted exactly once each.

**Per-model rows in the summary table.** The table renders a **separate row for each model used**. If a session used multiple models (for example, opencode using one orchestrator model and another for implementing or exploring under subagent-driven-development), the table renders one row per model for that session, with tokens divided accordingly.

Columns (`Model` is singular):

```
| Stage | Session | Harness | Model | Input | Output | Cache Read | Cache Write | Total | Source |
```

**Subagents: rolled up + JSON breakdown.** The table shows each model's divided tokens. The JSON carries the `children` array (session id, model, tokens) for SDD implementer/reviewer provenance.

The ledger is append-and-refresh only: never delete or rewrite another session's record.

### Audit comment format

A markdown table above, JSON below in a collapsed `<details>` block.

- The table is the human-scannable view.
- The JSON is the append-only machine-readable source of truth. The table is regenerated from it on every update.
- A row whose source is `unavailable` renders honestly (em-dashes, `unavailable` source) rather than as zeros, and is excluded from the totals row.

## Requirements

- [ ] **Ledger merge:** exactly one record per `(session_id, stage)`. Upsert, never duplicate. Stable ordering by workflow stage, then timestamp.
- [ ] **Render:** a markdown table with a separate row for each model used (`stage, session, harness, model, input, output, cache read, cache write, total, source`) plus a totals row, followed by a collapsed `<details>` block holding the ledger JSON in a fenced ```json block.
- [ ] **Multi-model sessions:** when `model_breakdowns` contains multiple models, render a row for each model with its divided tokens.
- [ ] **Round-trip:** the ledger JSON parses back out of a rendered comment body. Unparseable or absent JSON yields an empty ledger rather than an error.
- [ ] **Comment lookup** by marker content only. Never positional, never `--edit-last`, never the plan comment.
- [ ] **Upsert** through `gh api` against `repos/{owner}/{repo}/issues/{n}/comments`. PR conversation comments are issue comments, so one code path serves both `issue:N` and `pr:M` targets.
- [ ] **`--dry-run`** mode prints the body without posting.
- [ ] **Size limit:** GitHub's 65,536-character comment limit is a hard error to report, never a reason to trim or summarize the ledger.
- [ ] **No writes elsewhere:** never write usage into an issue body, a PR description, or the plan comment.
- [ ] **No local ledger state:** the GitHub comment is the ledger.

## Non-goals

- No price-list cost computation (pass through reported cost only).
- No aggregation dashboard (the JSON is machine-readable; scripts can come later).
- No changes to issue bodies, PR descriptions, or plan comments.
- No harness-specific logic. That all lives in #180's adapters.

## Testing

- **Ledger tests:**
  - append a record
  - refresh a record in place by `(session_id, stage)`
  - regenerate the table from JSON
  - render the `unavailable` path
- **Table rendering tests:**
  - a multi-model session renders separate rows per model with divided tokens
  - a single-model session renders one row
  - the totals row correctly sums across all model rows
  - an `unavailable` row renders honestly
- **Round-trip test:** render a ledger, then parse it back out of the rendered body.
- **Posting tests** against a stubbed `gh` on `PATH` that records its argv:
  - creates when no audit comment exists
  - PATCHes the existing one when it does
  - never selects a plan comment (`<!-- BEGIN PLAN -->`) as the audit comment
  - `--dry-run` performs no write
- Executable support file: run `just test-unit` and `just test` per docs/TESTING.md.
