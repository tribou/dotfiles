# Remove legacy docker-machine functions from `commands.sh`

## Summary
Delete the old `docker-machine` functions from `commands.sh`. Docker Machine was archived upstream in 2021 and is no longer maintained, so these helpers are dead code.

## Background
`docker-machine` has been deprecated and archived since 2021 and receives no fixes or updates. Any functions in `commands.sh` that wrap it can't be relied on and clutter the file. Docker Desktop and the Docker CLI with contexts (`docker context`) cover the use cases it served.

## Scope
- Identify every function in `commands.sh` that calls `docker-machine` or exists only to support it (for example, helpers that set up its environment or wrap `docker-machine env`).
- Remove those functions, along with any aliases, completions, comments, or variables that exist only for them.
- Check the rest of the repo (other shell files, rc files, docs, READMEs) for references to the removed functions and clean them up.

## Out of scope
- Adding replacements for the removed functionality.
- Changing unrelated Docker functions in `commands.sh`.

## Acceptance criteria
- [ ] `commands.sh` contains no `docker-machine` calls or functions that wrap it.
- [ ] No remaining references to the removed function names anywhere in the repo (`grep -rn` for each name returns nothing).
- [ ] `commands.sh` still sources cleanly in a new shell (`bash -n commands.sh` passes, and a fresh login shell shows no errors).
- [ ] Remaining Docker-related functions still work as before.

## Notes
- Before deleting, grep for each function name to confirm that nothing else, such as other scripts or shell config, still calls it.
- If any function turns out to be used for a purpose other than `docker-machine`, keep it and note that in the PR.
