# Split lib/commands.sh monolith into focused modules

## Problem

`lib/commands.sh` is 1,384 lines with 61 functions and 135 aliases spanning unrelated domains: git, npm, docker, tmux, AWS, DigitalOcean, terraform, SSH, and general shell utilities. As a result:

- It can't be tested in isolation.
- It is hard to review.
- Unrelated changes produce merge conflicts.

This issue applies the lib module organization standard in #153 (boundaries, size, naming, load order). It is the first concrete application of that standard. If anything here conflicts with #153, #153 wins.

## Prerequisite: fix load order (land first, as its own change)

`lib/index.sh` must source underscore-prefixed files (`_*.sh`) **first and explicitly**, before the remaining modules.

Under `en_US.UTF-8`, the current `ls`/glob ordering sorts `_shared.sh` 10th of 11, not first. Any split that adds a source-time dependency on `_shared.sh` could therefore break silently.

- The ordering fix and a test for it must merge before any module is split out.
- The test should fail if `_shared.sh` is not sourced before every non-underscore module.

## Scope

Split `lib/commands.sh` into these modules:

| File | Contents |
|---|---|
| `lib/git.sh` | Git aliases and functions (co, merge, branch management, commit helpers) |
| `lib/npm.sh` | npm/node detection and helpers |
| `lib/docker.sh` | Docker/container helpers |
| `lib/tmux.sh` | tmux session and window management helpers (large, ~71 keyword hits) |
| `lib/cloud.sh` | AWS, DigitalOcean, terraform, and SSH cloud helpers |
| `lib/repo.sh` | Repo scaffolding: the `.gitignore` generator (~L712–745) and `mkrepo` |
| `lib/agent.sh` | Agent state: the Claude keep-alive loop (~L375–388) and related helpers |
| `lib/commands.sh` | Only what fits none of the above (general shell utilities) |

Constraints:

- **`cloud.sh` stays one file** until it nears the ~300-line cap (per #153's boundary rule). Only then does it split by tool. Do not pre-split the small terraform/ssh pieces.
- **`repo.sh` is required.** The `.gitignore` generator and `mkrepo` must not end up in the general `commands.sh` bucket.
- `lib/index.sh` already globs `lib/*.sh` (excluding `index.sh`), so new files are picked up automatically once the prerequisite is in place.
- The line references (~L712–745, ~L375–388) are approximate. Re-locate the code before moving it.

## Out of scope

- Changing function signatures or alias names. This is purely a file reorganization with no behavior change.
- Pre-splitting `cloud.sh` by tool.

## Acceptance criteria

- [ ] The prerequisite (`_*.sh` sourced first, with a test) has merged before the split.
- [ ] Every module listed above exists, and `commands.sh` holds only general shell utilities.
- [ ] All 61 functions and 135 aliases are still defined, with identical names and signatures.
- [ ] No `lib/*.sh` file exceeds ~300 lines (soft cap per #153), checked with `wc -l`.
- [ ] `_shared.sh` is sourced before every non-underscore module.
- [ ] `bashcheck` passes on each new and modified file. `bashcheck` is the project linter, not `bash -n`.
- [ ] `just test-unit` and `just test` pass.
- [ ] In a new shell session, all existing aliases and functions still work.

## Verification steps

1. Run `just test-unit`.
2. Run `just test`.
3. Open a new shell and confirm the aliases and functions work.
4. Run `wc -l lib/*.sh` and confirm every file is at or under ~300 lines.
5. Confirm `_shared.sh` is sourced before every non-underscore module.
6. Run `bashcheck` on each new file.

- See `lib/index.sh` for how sourcing works.
- A before/after comparison of defined function and alias names is a cheap way to confirm nothing was dropped or renamed. For example, diff the output of `declare -F` and `alias` in a fresh shell.
