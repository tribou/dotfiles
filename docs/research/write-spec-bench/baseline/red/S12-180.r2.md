# feat(skills): cross-harness agent usage probe with per-harness adapters

## Summary

A single, executable TypeScript script run directly by bun (`#!/usr/bin/env bun`), `skills/agent-usage-audit/scripts/agent-usage-audit`, that probes the running agent harness for this session's model and token usage and emits one normalized JSON audit record on stdout.

Part 1 of 3, split out of the original combined spec:

- **#180 (this issue): probe core + harness adapters**
- **#181: ledger, rendering, and the GitHub audit comment**
- **#182: the shared `agent-usage-audit` skill and wiring the three workflow skills**

Downstream issues #181 and #182 consume the JSON record shape defined here.

## Motivation / Context

We want an audit trail of which model ran each workflow stage and how many tokens it consumed. Today, across our three harnesses (opencode, Claude Code, agy), that information is trapped in three different stores in three different formats. This script normalizes them into one standard JSON record.

**Truthfulness principle:** If a probe succeeds, its numbers are real. If it fails (missing store, missing session, unreadable file, dropped rows), it emits `"source": "unavailable"` with an honest reason. It NEVER fabricates, estimates, or guesses numbers. An incomplete audit is useful; a fabricated one is poison.

## Prior art adopted

1. **ccusage** ([anthropics/ccusage](https://github.com/anthropics/ccusage)) supports multiple harnesses, calculates cost across cache buckets, and parses Claude JSONL and opencode SQLite. We don't take an npm dependency, but we **defer to ccusage when the user has it installed**: `ccusage session --id <id> --json` is tried first for both harness types.
   → **Adopt: probe prefers ccusage when available; built-in adapters are the zero-dependency fallback.**
2. **agent-walker's agy field map** ([agent-walker](https://github.com/miiiiiiich/agent-walker)): agy's `gen_metadata` blobs are unlabeled protobuf. agent-walker documents the reverse-engineered field numbers (#1 system, #2 new input, #5 cache-read, #9 output, #10 thinking, #11 response-id, #19/#21 model) **with a per-row self-check**. The stored total (#3) must equal output+thinking, else the row is skipped as parse drift. Guessed numbers are never posted.
   → **Adopt: agy adapter uses this field map + self-verification; rows failing verification are dropped, not guessed.** (agy also emits exact usage in headless `--output-format json` result envelopes. That covers print-mode runs, not interactive sessions.)
3. **Transcript dedup by message/request id** (tokenomics-coach, Claude Agent SDK docs): streaming writes each turn to JSONL multiple times with identical usage, so naive summation silently multiplies totals. Parallel tool calls share one message id.
   → **Adopt: hard requirement + fixture test for the built-in Claude Code adapter.**
4. **pr-cost** ([jabertuhin/pr-cost](https://github.com/jabertuhin/pr-cost)) is a Claude Code plugin that embeds per-branch cost blocks into PR descriptions via Stop/PostToolUse hooks. Hook-based capture doesn't port across harnesses (our skills must stay harness-agnostic). Critically, **embedding in the PR description pollutes the squash-merge commit message prefill**, which this repo's workflow explicitly avoids.
   → **Validates the dedicated-comment choice** made in #181. Its local per-branch JSONL ledger with read cursors is noted as prior art; our ledger remains the GitHub comment (no local state to sync).

## Data source strategy (must work across opencode, Claude Code, and agy)

Probed on this machine: all three harnesses keep local per-session/conversation stores.

| Harness | Store | Exactness |
|---|---|---|
| opencode | `~/.local/share/opencode/opencode.db`, `session` table: `model`, `tokens_input/output/reasoning`, `tokens_cache_read/write`, `cost`; subagents linked via `parent_id` (also: `storage/message/` JSON per ccusage) | Exact |
| Claude Code | `~/.claude/projects/<dir-slug>/<session>.jsonl`; each assistant message has `message.model` + `message.usage`; sum with dedup-by-message-id | Exact |
| agy (Antigravity CLI) | `~/.gemini/antigravity-cli/conversations/<uuid>.db`, `gen_metadata` protobuf blobs; agent-walker field map + #3 self-verification | Best-effort, self-verified |

**Architecture: probe script with per-harness adapters, emitting one normalized JSON audit record.**

- **Probe order: `ccusage session --id` (if installed) → built-in adapters → `source: unavailable`.** Never fabricate; failed probes emit honest `unavailable` records.
- Detect harness via env markers (`OPENCODE=1`, Claude Code markers) and store presence.
- Skills never contain harness-specific logic; it all lives in this script.
- **Per-model token division:** Tokens must be divided by model so downstream comment rendering (#181) can render a separate row for each model used.
  - **opencode:** parent session tokens attribute to the orchestrator model; child session tokens attribute to their respective models. Model strings encoded as JSON (e.g. `{"id":"glm-5.3",...}`) are normalized to their model ID.
  - **Claude Code:** tokens are accumulated by `message.model` across deduplicated turns.
  - **agy:** tokens are accumulated by model across verified `gen_metadata` rows.
  - **ccusage:** `modelBreakdowns` from ccusage is mapped into `model_breakdowns`.

### Verified during planning (2026-09-06)

Empirical findings from probing the real stores on this machine; they tighten the spec above:

- **Claude Code dedup key is the pair `(message.id, requestId)`**, not the message id alone. A real transcript held 75 `type: "assistant"` lines for 32 unique pairs, so naive summation inflates totals ~2.3×. Subagent turns are distinguished by the top-level `isSidechain` flag in the same transcript.
- **agy's usage counters are nested two levels deep**, which the agent-walker map alone does not state. `gen_metadata.data → #1 → #4` holds the usage block (`#2` new input, `#3` stored total, `#5` cache read, `#9` output, `#10` thinking), and the model name is at `#1 → #19` (fallback `#21`). The `#3 == #9 + #10` self-check verified on 74/74 rows of a real conversation.
- **No `sqlite3` binary in the CI image.** `bun` is a mise-managed core runtime (`mise-config.toml` installs it on every machine, including the Docker CI image via the un-scoped `mise install`), and its built-in `bun:sqlite` module suffices. Both SQLite stores are opened read-only. Bun executes TypeScript directly, so no build step is needed.
- **`.gitignore` ignores `*.db`**, so SQLite fixtures cannot be committed as binaries. A committed text generator builds them at test time.

## Requirements

- Cross-harness: opencode, Claude Code, agy.
- Probe order: ccusage when available → built-in adapters → `source: unavailable` record; never fabricate.
- Built-in Claude Code adapter must dedup by `(message.id, requestId)` (fixture-tested).
- agy adapter uses the agent-walker field map with per-row `#3` self-verification. Unverifiable rows are dropped, and a record with zero verified rows is `unavailable`.
- Subagent usage is rolled into the parent record's totals with a per-child breakdown in a `children` array (Claude Code: `isSidechain` turns; opencode: sessions linked by `parent_id`).
- **Per-model token breakdown (`model_breakdowns`):** When a session uses multiple models (e.g. opencode orchestrator vs subagents, Claude Code turn models, agy row models, ccusage `modelBreakdowns`), tokens and costs must be divided by model in a `model_breakdowns` array (`[{ model, tokens, cost_usd }]`). opencode normalizes model IDs (extracting `id` if JSON-encoded). Aggregate `tokens` remains the sum across all models.
- One normalized record shape shared by every adapter, carrying: schema, stage, harness, session id, source, models, model_breakdowns, tokens (`input`, `output`, `cache_read`, `cache_write`, `reasoning`, `total`), cost passthrough, children, timestamp.
- Token normalization rule: `output` includes reasoning, `reasoning` repeats that subset for information, `total = input + output + cache_read + cache_write`.
- Bun + TypeScript only. Bun executes TypeScript directly (no build step); no npm dependencies, no pip installs, no `jq`, no `sqlite3` binary (`bun:sqlite` is built in).
- Environment overrides for harness, session id, and every store path, so the adapters are testable against fixtures.

## Non-goals

- No price-list cost computation. Pass through harness/ccusage-reported cost only (often 0 on subscriptions); ccusage `--mode calculate` can be a later opt-in.
- No hook-based capture (doesn't port across harnesses).
- No GitHub posting, ledger, or rendering; that is #181.
- No skill authoring or workflow-skill wiring; that is #182.

## Testing

- bats unit tests with fixture stores: generated opencode.db, committed fixture transcript.jsonl (incl. duplicate `(message.id, requestId)` streaming rows and a sidechain row), generated agy db (verifiable + drifted blobs).
- Fixture SQLite databases are built at test time by a committed Bun/TypeScript generator (`bun:sqlite`), because `.gitignore` ignores `*.db`.
- `model_breakdowns` verified across adapters, proving tokens are divided per model when multiple models are used (e.g. opencode parent on one model and child on another).
- `unavailable` path covered for each harness: missing store, missing session, unreadable store, all-rows-dropped.
- Executable support file → `just test-unit` + `just test` per docs/TESTING.md.
