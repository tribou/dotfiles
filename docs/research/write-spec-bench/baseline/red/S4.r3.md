# Enable SSH agent forwarding on Mac and add a stable `SSH_AUTH_SOCK` symlink on Linux so tmux survives reconnects

## Problem

When SSHing from the Mac to a Linux host and attaching to tmux, the forwarded agent socket stops working after a reconnect:

- The Mac SSH config does not enable `ForwardAgent`, so no agent is forwarded by default.
- Even with forwarding, sshd creates a new socket path (e.g. `/tmp/ssh-XXXX/agent.NNNN`) on every login. Long-lived tmux sessions keep the old, now-dead `SSH_AUTH_SOCK`, so `git`, `ssh`, and signing fail inside existing panes until the environment is manually fixed.

## Goal

Agent-backed auth (git over SSH, onward ssh hops, commit signing) works in tmux panes before and after reconnecting, with no manual `export SSH_AUTH_SOCK=...`.

## Scope

1. **Mac SSH config:** enable `ForwardAgent` in the dotfiles-managed ssh config.
2. **Linux shell startup:** on SSH login, point a fixed symlink (e.g. `~/.ssh/ssh_auth_sock`) at the current `$SSH_AUTH_SOCK`.
3. **Linux tmux/shell env:** make tmux and its panes use the stable symlink path rather than the per-login socket.

## Proposed approach

### Mac

- In the Mac ssh config, enable forwarding. Prefer limiting it to trusted hosts rather than `Host *`:
  ```
  Host <trusted-linux-host> ...
      ForwardAgent yes
  ```
- Confirm the Mac config is the one managed/symlinked by the dotfiles repo, and that the key is loaded in the agent (`AddKeysToAgent` / `UseKeychain` as already configured).

### Linux

- In an early-sourced shell file (e.g. `.bashrc`/`.zshrc`/`.profile`, whichever the repo uses for login and interactive shells), add logic like:
  ```sh
  if [ -n "$SSH_CONNECTION" ] && [ -S "$SSH_AUTH_SOCK" ] \
     && [ "$SSH_AUTH_SOCK" != "$HOME/.ssh/ssh_auth_sock" ]; then
    mkdir -p "$HOME/.ssh" && chmod 700 "$HOME/.ssh"
    ln -sfn "$SSH_AUTH_SOCK" "$HOME/.ssh/ssh_auth_sock"
  fi
  export SSH_AUTH_SOCK="$HOME/.ssh/ssh_auth_sock"
  ```
  The export should apply only when the symlink exists or the session is SSH, so local non-SSH sessions with their own agent are not broken.
- In `tmux.conf`, ensure `SSH_AUTH_SOCK` is not overwritten with a stale value on new windows. Either remove it from `update-environment` or keep it there only if the shell snippet re-points it to the symlink. Verify which behavior the current config has.
- Make the logic idempotent and safe to source repeatedly (nested shells, tmux panes).

## Acceptance criteria

- [ ] From the Mac, `ssh <linux-host> 'ssh-add -l'` lists the Mac's keys.
- [ ] After login, `~/.ssh/ssh_auth_sock` exists and resolves to the current session's socket.
- [ ] Start tmux, disconnect, reconnect, and reattach. In an existing pane, `ssh-add -l` and `ssh -T git@github.com` succeed without manual changes.
- [ ] A second concurrent SSH session does not break the first (the symlink points at a live socket).
- [ ] Local (non-SSH) shells on Linux are unaffected: no stray symlink created and `SSH_AUTH_SOCK` is not clobbered.
- [ ] Sourcing the shell config multiple times produces no errors or changes.
- [ ] Changes are applied through the dotfiles repo, not hand-edited on hosts.

## Risks and notes

- **Security:** agent forwarding lets root on the remote host use the agent while connected. Restrict it to trusted hosts and avoid `Host *`.
- **Stale symlink:** if the last connection closes, the symlink dangles until the next login. This is expected, and the snippet should relink on the next login.
- **Concurrent sessions:** the most recent login wins. If it disconnects first, the link is dead until another login or shell start. Document this, and consider a helper (e.g. `fixssh`) that relinks from the newest live `/tmp/ssh-*/agent.*` socket if it matters.
- The symlink is user-writable, so keep `~/.ssh` at `0700`.

## Out of scope

- Switching to `ProxyJump` or agent-less alternatives.
- Managing agent lifecycle on the Mac.
- Windows or other non-Mac/Linux hosts.
