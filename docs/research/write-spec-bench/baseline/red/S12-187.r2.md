# perf(test): docker-based tests running very slow locally

## Summary
Local Docker-based test execution (`just test`) takes ~3m 42s because of redundant downloads, non-idempotent compilation, and full Homebrew provisioning. `just test` also fails when run from linked Git worktrees (#189) because the `.git` pointer can't be resolved and Git's safe-directory check rejects the repo. This work reduces local test runtime to ~24s–36s (6x–9x faster), keeps test integrity, adds a full clean-state test option, and fixes test execution from linked worktrees.

## Motivation / Context
A local `just test` run took 3m 41.7s, with 92.8% of the time spent in Ansible provisioning:

1. The ephemeral container reinstalled Homebrew on Linux from scratch, plus 27 formulae and gcc (~89s). Neither `goss.yaml` nor the Bats integration tests assert any of it.
2. `mise install` re-downloaded runtimes (node, go, ruby), 18 global npm packages, and recompiled Ruby native gems, with no volume caching (~41s).
3. `apt` ran an unconditional `update_cache: true` for missing Linux prereqs (~26s).
4. `roles/dotfiles/tasks/nvim.yml` checks a nonexistent path (`creates: "{{ dotfiles_home }}/dev/go/bin/gopls"`) instead of `which gopls` / `$GOBIN`. This forces `gopls` to be recompiled from source on every run (~15s).
5. Linked worktree failure (#189): running `just test` from a linked worktree (e.g. under `.worktrees/`) fails at `dotfiles : Clone TPM` with `fatal: not a git repository`. In a linked worktree, `.git` is a pointer file to the common git directory (`<main-repo>/.git/worktrees/...`). The container only mounts `.:/dotfiles`, so Git inside it cannot resolve the host's common git directory.

Profiling showed RAM is not the bottleneck (peak container RAM ~1.06GB with 8GB free on the host, no swap activity). Burst CPU and network I/O were heavily saturated.

## Requirements
- Local `just test` finishes in under 45 seconds (target ~25s–35s) on cached runs.
- Fix the `gopls` idempotency check in `roles/dotfiles/tasks/nvim.yml` to check actual binary existence (`which gopls`).
- Add `cache_valid_time: 86400` to the apt task in `roles/dotfiles/tasks/prereqs.yml`.
- Mount persistent `.ci-cache/` volumes in `docker-compose.yml` for mise runtimes/cache, tmux plugins, and go/coc.
- Set default `DOTFILES_ANSIBLE_EXTRA_ARGS: "--skip-tags brew,rust"` in `docker-compose.yml`, matching GitHub Actions CI (`ubuntu-tests.yml`).
- Add a fast `ansible-playbook --syntax-check` to `just test-unit` to guard against regressions in the skipped roles (`brew.yml`, `rust.yml`).
- Add a `just test-clean` recipe to `justfile` that wipes `.ci-cache/` and runs a full cold test without `--skip-tags`.
- Support linked Git worktrees (#189):
  - In `justfile`, resolve the common Git directory (`git rev-parse --path-format=absolute --git-common-dir`) and bind-mount it read-only into the container for `test`, `test-clean`, and `dev`.
  - Set `safe.directory: "*"` in the container environment (`docker-compose.yml` and `Dockerfile`) so cross-UID / worktree access doesn't trigger dubious-ownership errors.
- Docker build hygiene: add `.worktrees/`, `.claude/`, and `.ci-cache/` to `.dockerignore` so child worktrees don't inflate the build context.

## Non-goals
- Rewriting the Docker base image to bake in all user runtimes (keeps flexibility for local dotfile hacking).
- Modifying remote CI workflows beyond aligning flags (GitHub Actions already skips brew).
- Changing dotfiles installation logic on macOS hosts.

## Acceptance criteria / Testing
- All 54 Goss infrastructure assertions pass in `just test`.
- All 25 Bats integration tests pass in `just test`.
- `just test-unit` runs syntax validation across all Ansible task files.
- `just test-clean` clears `.ci-cache/` and completes a full cold-start bootstrap.
- `just test` passes from both the primary checkout and a linked worktree (`.worktrees/`).
- Benchmark confirms runtime drops from ~3m 42s to ~25s–35s on cached runs.

## Design notes / Decisions
- **Integrity risk is low and accepted.** The gopls and apt changes are pure idempotency fixes. Skipping brew/rust matches existing GitHub Actions CI, since Goss/Bats don't test brew packages, and the syntax check in `test-unit` covers the skipped roles. Volume caching makes local runs converge idempotently, consistent with the existing `.ci-cache/nvim` precedent, and the cache can be wiped on demand (`just test-clean`).
- **Clean-state fallback:** a dedicated `just test-clean` recipe, rather than a flag or env toggle.
- **Child worktree tests:** tests inside child worktrees have never been run accidentally from the parent, because the Bats and Goss runners use explicit non-recursive paths (`tests/*.bats`, `tests/integration/`). This change enables intentionally running tests from inside a worktree. The `.dockerignore` additions keep worktree files out of the build context.
