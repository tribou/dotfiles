# refactor(packages): make mise the primary package manager

## Summary

Make mise the primary package manager for runtimes, language-level global packages, and Homebrew-managed formulae. Use mise tool backends (`[tools]`) for version-switched CLIs and mise's built-in `brew:` manager (`[bootstrap.packages]`) for formulae that still need Homebrew artifacts. Retain the existing Homebrew cask flow.

## Motivation / Context

- Default Node, Python, and Ruby packages are managed separately from `mise-config.toml`. Homebrew owns a broader package set and bootstraps Ansible before mise is installed.
- Mise deprecates default Python package files (warnings from 2026.11.0, removal in 2027.11.0), so package behavior needs to move into TOML.
- Mise 2026.7.5 provides `mise bootstrap packages`. Its built-in `brew:` manager installs Homebrew formulae into the canonical prefix without requiring Homebrew. `brew-cask:` exists but has narrower platform and lifecycle coverage.
- Consolidating ownership and bootstrap under mise reduces overlap, makes versions explicit, and establishes one primary package manager. It also lets mise replace the separate Ansible Homebrew modules and Brewfile flows for formulae.

## Architecture / Ownership

- `mise-config.toml` is the single source of truth for runtimes, bootstrap tools, standalone CLIs, language packages, and shared Homebrew formula artifacts.
- Backend conventions:
  - canonical mise registry names for standalone CLIs
  - explicit `npm:` and `gem:` identifiers for ecosystem CLIs
  - `pipx:` for isolated Python CLIs
  - Python tool-level `postinstall` for libraries the managed interpreter must import
- Ansible orchestrates installation and cleanup. It does not duplicate the mise tool list in role variables.
- Mise's `brew:` manager owns residual formulae under `[bootstrap.packages]`, which remain in the shared Homebrew prefix after portable CLIs move to `[tools]`.
- The Homebrew CLI and Brewfile flow own only casks. Casks stay in the Brewfile and do not move to `brew-cask:` in this issue.
- Native OS package managers remain responsible for bootstrap prerequisites and system-level dependencies.

## Migration / Failure Handling

1. **Inventory.** Cover every formula in the core, Linux-specific, macOS-specific, and optional declarations. Classify each as a `[tools]` candidate or a `[bootstrap.packages]` formula, and record the selected key and expected executable.
2. **Qualify.** Install each `[tools]` candidate and run its executable/version smoke check on both macOS and Linux. Only dual-platform successes move to `[tools]`. Everything else stays a `brew:` bootstrap package.
3. **Greenfield bootstrap.** Install the verified standalone mise binary and expose the repository's `mise-config.toml` at mise's global config location. On existing machines, verify that mise exposes `mise bootstrap packages` first. If it doesn't, reinstall or update mise through the verified standalone path.
4. Run `mise bootstrap packages apply --yes`, then `mise install --yes`.
5. Run the initial playbook through `mise exec`, so mise-provisioned Ansible is available without shell activation or Homebrew.
6. In Ansible, repeat package application and tool installation before smoke checks and before cleanup.
7. **Move declarations.**
   - Core and platform formulae go into the repository mise config.
   - Optional formulae go into the mise optional-config example, not into the core set.
   - The optional Brewfile keeps casks only.
8. **Cleanup.** After package application, tool installation, and smoke checks all succeed, use an already-installed Homebrew executable to converge the previously managed Homebrew copies of tools moved to `[tools]` to absent.
   - Do not install Homebrew solely for cleanup.
   - If any mise phase or smoke check fails, perform no cleanup and fail with package/tool context.
9. Surface targeted cleanup failures, including dependency-blocked removals, as actionable warnings without aborting unrelated provisioning.
10. Never run `mise bootstrap packages prune --manager brew`, since it can remove manually installed formulae. Limit automatic cleanup to the known formulae that moved to `[tools]`.
11. Keep package and tool phases explicit in both greenfield bootstrap and Ansible, so package, tool, and smoke-check failures stay distinguishable.
12. **PATH.** Add the canonical Homebrew prefix directly to shell `PATH` when it exists (`/opt/homebrew/bin` on Apple Silicon macOS, `/home/linuxbrew/.linuxbrew/bin` on Linux). Do not depend on `brew shellenv`: mise-installed formulae create shared-prefix links rather than shims, and Linux may have no Homebrew executable.
13. Install or invoke the real Homebrew CLI only for the retained macOS cask flow. Linux formula provisioning must not require Homebrew.

## Requirements

**Language packages**
- Move default Node, Python, and Ruby gem package declarations into mise configuration.
- Use direct `npm:` and `gem:` entries for executable packages, and `pipx:` only for Python CLI applications.
- Install `pynvim` via the Python tool-level `postinstall`, so `mise exec -- python -c "import pynvim"` succeeds.
- Delete the three legacy default-package files, along with their symlink, doctor, and goss assertions, once their entries are in mise config.

**Formulae and tools**
- Audit every repository-managed Homebrew formula declaration (core, Linux, macOS, optional examples).
- Move portable version-switched tools to `[tools]` only after install and smoke checks pass on macOS and Linux. If qualification fails on either OS, keep the formula as a `brew:` bootstrap package.
- Put all retained formulae in `[bootstrap.packages]` with explicit `brew:` keys, separate from `[tools]`.
- Use canonical mise registry names for standalone CLIs so mise follows its maintained backend preference and fallback metadata.
- Preserve floating channels: Node `lts`, Ruby major `3`, and standalone CLI and language-package entries `latest` unless a concrete compatibility constraint requires otherwise.
- Define mise as the primary package manager for future additions.

**Bootstrap and cleanup**
- Make greenfield bootstrap mise-first: install standalone mise before Homebrew, provision Ansible through mise, and invoke the initial playbook through `mise exec` (or an equivalently reliable non-interactive mise environment).
- Install Homebrew later in the Ansible role only when the macOS cask flow needs it.
- On existing machines, remove only formulae whose replacements moved into `[tools]`, and only after those replacements install and pass smoke checks.
- Run cleanup only when a real Homebrew executable already exists.
- Treat dependency-blocked removals as surfaced cleanup failures. Do not silently retain duplicate ownership, and do not abort unrelated provisioning.
- Use targeted cleanup rather than manager-wide prune, to preserve unrelated manually installed formulae.
- Use explicit phases everywhere: `mise bootstrap packages apply --yes`, then `mise install --yes`.
- Verify mise supports `mise bootstrap packages` before applying declarations, and update it via the verified standalone path when needed.

**Platform and semantics**
- The `brew:` manager supports Apple Silicon macOS and Linux x86_64/arm64, not Intel macOS. Apple Silicon is the only supported macOS architecture; do not retain a parallel Intel formula path.
- Account for mise package semantics:
  - package application is explicit
  - `latest` accepts an already-installed version
  - upgrades use `mise bootstrap packages upgrade`
  - formula pruning can remove packages installed by real Homebrew
- Keep casks out of this migration; do not add `brew-cask:` entries.

## Non-goals

- Removing Homebrew entirely.
- Moving macOS casks to mise.
- Replacing native OS package managers for bootstrap prerequisites or system packages.
- Introducing exact-version lock maintenance.
- Generating mise configuration from Ansible variables.
- Splitting core managed tools across repository-owned mise config fragments.
- Supporting Intel macOS through a separate Homebrew formula path.
- Treating the repository's mise config as authority to remove unrelated manually installed Homebrew formulae.

## Testing

- Each portable CLI migrated from a formula installs through `[tools]` and its executable/version command succeeds on both macOS and Linux.
- Every residual `brew:` package applies and reports installed on its selected OSes without a Homebrew executable.
- A greenfield bootstrap reaches and executes the Ansible playbook without Homebrew providing Ansible.
- Cleanup runs only after successful package application, tool installation, and smoke checks. It is idempotent, reports blocked removals, and never uses manager-wide prune.
- Canonical Homebrew prefix paths work without `brew shellenv`, and the Homebrew CLI is installed only for the macOS cask flow.
- Repository assertions and documentation reflect the new ownership split, including the optional-package examples.
- Focused Bats coverage for:
  - the single-source package policy
  - exact `[tools]` versus `[bootstrap.packages]` ownership
  - OS selectors
  - cask-only Brewfile content
  - bootstrap ordering
  - targeted cleanup safety
  - upgrade separation
  - PATH behavior
  - removal of legacy package-file links
- Update goss/integration assertions to verify that representative runtime, standalone CLI, npm, pipx, and gem executables resolve through mise, and that `pynvim` imports from the mise-managed Python.
- Exercise the qualified tool set, configured `brew:` package status, and smoke commands in both Apple Silicon macOS and Linux CI paths.
- Assert the macOS CI runner is arm64, so a future runner-label architecture change fails explicitly.

- Run the full install twice to verify Ansible/mise/Homebrew idempotence.
- Update `scripts/doctor.sh` so `[tools]` failures point to `mise install`, `brew:` package failures point to `mise bootstrap packages apply`, and no removed legacy symlink is expected.

## Decisions log

- **Source selection:** registry-first. Use canonical mise names for standalone CLIs and explicit `npm:`, `pipx:`, and `gem:` entries for language packages.
- **Migration evidence:** a formula moves to `[tools]` only after install and smoke checks pass on both macOS and Linux. Otherwise it stays a `brew:` package.
- **Bootstrap:** mise-first end to end. Ansible is provisioned and invoked through mise, and Homebrew is installed later only for casks.
- **Existing machines:** automatic targeted cleanup of migrated formulae, reporting dependency-blocked removals.
- **Versions:** preserve floating channels (Node `lts`, Ruby `3`, others `latest`).
- **Audit scope:** all formulae (core, platform-specific, optional). Casks stay in Homebrew.
- **Config architecture:** a single repository-managed `mise-config.toml`.
- **Casks:** formulae only; casks stay in the existing Brewfile flow rather than `brew-cask:`.
- **Architecture support:** Apple Silicon macOS only, with no Intel fallback.
- **Reconciliation:** targeted migration cleanup, not manager-wide `prune`.
- **Command boundary:** explicit phases (`mise bootstrap packages apply --yes`, then `mise install --yes`) rather than composite `mise bootstrap --yes`.
