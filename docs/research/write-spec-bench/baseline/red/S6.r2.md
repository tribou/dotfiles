# feat(shell): add `qq` one-off AI question command

## Summary

Add a `qq` shell command that sends a single, context-free question to the configured AI backend (`opencode` / `claude` / `agy`) and prints the answer.

- `qq` with no args opens a `qq> ` prompt.
- `qq some question` passes the typed text verbatim, with no shell escaping needed.
- Backend and model settings are shared with `commit` under renamed `DOTFILES_AI_*` env vars.
- The shared helpers move into a new `lib/ai.sh`.

## Motivation / Context

Raw idea (user's words):

> add a 'qq' command that uses the same model env vars and settings as 'commit'. When you run 'qq' with no parameters, it opens an input prompt that lets you ask a single question that gets passed to the configured AI agent harness as a one-off command and it returns the response. Open to an additional feature where you run 'qq this is a question' and it passes all parameters as a prompt. However, we'd need to consider whether it's too brittle with all of the escaping needed. or it could be "qq 'this is a question'" as a backup. The 'c' alias has worked fairly well in passing additional args to the commit message with minimal friction (even with some escaped character quirks), so I'm not too concerned. catching special characters that need to be escaped and throwing an error could be a good middle ground

Existing overlap: `commit` in `lib/git.sh` already resolves backend, model, and timeout via:

- `_dotfiles_commit_backend` (`DOTFILES_COMMIT_BACKEND`, default `opencode`; also `claude`, `agy`)
- `_dotfiles_commit_model` (`DOTFILES_COMMIT_MODEL`, per-backend defaults)
- `_dotfiles_commit_timeout` (`DOTFILES_COMMIT_TIMEOUT`, default 15s)
- `_dotfiles_spinner_wait` for the spinner

`c` joins args with `"$*"`.

## Requirements

### Shared AI settings (renamed)

- `DOTFILES_COMMIT_BACKEND` → `DOTFILES_AI_BACKEND` (same values: `opencode` default, `claude`, `agy`).
- `DOTFILES_COMMIT_MODEL` → `DOTFILES_AI_MODEL` (same per-backend defaults when unset).
- `qq` and `commit` resolve backend and model through the same shared helpers, so one setting drives both.

### Deprecated-name fallback

- If `DOTFILES_AI_BACKEND` / `DOTFILES_AI_MODEL` is unset but the old `DOTFILES_COMMIT_BACKEND` / `DOTFILES_COMMIT_MODEL` is set, use the old value and print a one-line deprecation warning naming the new variable to **stderr** (never stdout, so captured output stays clean).
- When the new name is set, it wins and no warning is printed.

### Timeouts (per-command)

- `qq` gets `DOTFILES_QQ_TIMEOUT`, default **60s** (commit's 15s is tuned for a one-line message).
- `commit` keeps `DOTFILES_COMMIT_TIMEOUT` (default 15s). Timeouts are not shared.
- Parsing is shared and parameterized by variable name and default: empty or non-numeric falls back to the default; `0` means no timeout (wait until the backend finishes; Ctrl-C still cancels).

### Structure

- New `lib/ai.sh` receives the shared helpers from `lib/git.sh`, renamed to `_dotfiles_ai_*`:
  - `_dotfiles_ai_backend` / `_dotfiles_ai_model` (read `DOTFILES_AI_*` with the deprecated-name fallback and warning)
  - `_dotfiles_ai_spinner_wait` (was `_dotfiles_spinner_wait`)
  - the shared timeout parser
  - `_dotfiles_qq` and the `qq` alias
- `lib/git.sh`: `commit` / `_dotfiles_commit_generate_message` call the `_dotfiles_ai_*` helpers. Commit-specific pieces (prompt, sanitize, `DOTFILES_COMMIT_TIMEOUT`) stay in `git.sh`.
- `lib/index.sh`: no change (it already sources every `lib/*.sh`).

### `commit` subcommands

- `commit backend X` now exports `DOTFILES_AI_BACKEND` (so it also switches `qq`).
- `commit status` also shows the `qq` timeout alongside the existing backend/model/timeout/available lines.

### `qq` behavior

- **No subcommands:** any input, e.g. `qq status of my PR`, is always a question.
- **Prompt wrapper:** prepend a short fixed instruction, e.g. "Answer concisely for display in a terminal. Prefer short answers; use code blocks for commands.", followed by the question. No env override.
- **Context-free:** pure Q&A with no repo/file access. Run the backend outside the user's cwd (e.g. from a temporary empty directory) and, where the backend CLI supports it, with tools disabled. Exact per-backend flags are an implementation detail to verify against each CLI's current docs. The user's shell cwd is unchanged after `qq` returns.

### Runtime flow

1. Obtain the question: interactive shells use the raw history line; non-interactive calls use `"$*"`. If the result is empty, fall through to the `qq> ` prompt.
2. Resolve backend and model via `_dotfiles_ai_*`.
3. Launch the backend in the background from a temporary empty directory with wrapper + question.
4. Show the existing spinner on **stderr** (e.g. `Asking Opencode...`).
5. Print the answer to **stdout** as-is: multi-line, code blocks intact. Unlike `commit`, it is not truncated to one line; only leading/trailing blank lines are trimmed.
6. Clean up the temp dir and output file.

### Output streams

Stdout is answer-only. Everything else (spinner, warnings, errors) goes to stderr. With the raw-history args form, a trailing `| cmd` on the `qq` line is part of the question, so piping the answer works only with bare `qq` or non-interactive calls.

### Errors

Unlike `commit` (which falls back to `c`), there is no manual fallback. Every `qq` error prints one line to stderr and exits non-zero:

| Case | Message (stderr) | Exit |
|---|---|---|
| Empty input / Ctrl-D / Ctrl-C at `qq>` | (none) | 1 (130 on Ctrl-C) |
| Leading-space guard trips | `qq: question not in history (leading space?); run bare qq instead` | 1 |
| Backend CLI not installed | `qq: <backend> not found` | 1 |
| Ctrl-C while waiting | `qq canceled` | 130 |
| Timeout | `qq: <backend> timed out after <N>s` | 124 |
| Backend fails / empty output | `qq: <backend> returned no answer` | 1 |

### No-arg input prompt

Bare `qq` shows a `qq> ` prompt and reads one line with `read -e -r` (readline editing; text is not parsed by the shell, so no escaping is needed). Enter submits. Empty input, Ctrl-D, or Ctrl-C exits without calling the backend.

### Args-as-prompt via raw history line

`qq this is a question` captures the question exactly as typed, not via `"$*"`:

- Define `alias qq='_dotfiles_qq #'`. The trailing `#` makes bash treat the rest of the line as a comment, so it is not parsed, expanded, globbed, or redirected.
- `_dotfiles_qq` reads the current command line from `history 1` (with `HISTTIMEFORMAT` neutralized), strips the history number and everything up to and including the `qq` invocation, and uses the remainder verbatim as the question.
- Result: `? * $VAR > < ; & | ' "` all pass through literally. A throwaway spike verified `what's up`, `a > b means what`, `$HOME`, `*`, `?`, `;`, and double quotes arriving verbatim, with no redirect file created.
- If the remainder is empty (bare `qq`), fall through to the `qq> ` prompt.

### Leading-space guard

The user's `bash_profile` sets `HISTCONTROL=ignorespace`, so a command typed with a leading space is not saved to history and `history 1` returns the *previous* entry (the spike showed this silently re-sending an older question). `_dotfiles_qq` must detect that the current command was not recorded and exit non-zero with the error above telling the user to run bare `qq`. It must never send a stale history entry.

### Non-interactive fallback

In scripts / non-interactive shells (aliases and history inactive), `_dotfiles_qq` is called directly with real args and uses `"$*"` as the question.

### Known limitations (documented, not worked around)

- **`!word`:** bash history expansion runs before the comment is recognized, so `qq is !important bad` fails with bash's own `event not found` error and nothing is sent. This is visible, not silent.
- **Line continuation:** a trailing `\` continuation is not supported in the args form (only the first physical line is recorded). Use bare `qq` for such input.

### Docs

Update `docs/DEVELOPMENT.md` with:

- renamed vars and the deprecation fallback
- `DOTFILES_QQ_TIMEOUT`
- a short `qq` usage note: args form vs. bare `qq`, the `!word` and leading-space limits, and that piping works only with bare `qq`

## Non-goals

- Multi-turn chat / follow-up questions
- Repo-aware answers (file reads, tools)
- Streaming output
- Markdown rendering
- Reading the question from piped stdin
- `qq` subcommands
- An env override for the wrapper prompt
- Working around `!word` bash history expansion

## Testing

Bats tests, written TDD-first, following the existing pattern (source libs in `bash -c`, stub `claude` / `opencode` / `agy` as shell functions).

- **Update existing tests** for the renamed vars/helpers: `tests/commit_backend.bats`, `tests/commit_command.bats`, `tests/commit_generate_message.bats`, `tests/spinner_wait.bats`.
- **Deprecation fallback:**
  - Only the old name set → its value is used and a warning is printed on stderr.
  - New name set → it wins and no warning is printed.
  - The warning never appears on stdout.
- **New `tests/qq_command.bats`:**
  - Non-interactive args form uses `"$*"`.
  - Raw-history path, exercised under `bash -i` with an rcfile (as in the spike): `?`, `*`, `$HOME`, `>`, `;`, `'` arrive verbatim, and no redirect file is created.
  - Leading-space guard errors and does **not** send the previous history entry.
  - Bare `qq` with empty input exits 1 without calling the backend.
  - The terminal wrapper text is included in the prompt sent to the backend.
  - The backend runs in a directory other than `$PWD`, and the caller's cwd is unchanged afterwards.
  - Multi-line answers are preserved; leading/trailing blank lines are trimmed.
  - Error table rows: backend not found → exit 1; timeout (short `DOTFILES_QQ_TIMEOUT`) → exit 124; empty answer → exit 1.
  - Stdout contains only the answer.
- **`tests/lib_modules.bats`:** add a `type qq` check for `ai.sh`.
- **Quality gates:** `bashcheck` on changed lib files, then `just test-unit` and `just test`.

## Acceptance criteria

- [ ] `qq` (bare) prompts at `qq> ` and answers a single typed question.
- [ ] `qq <text>` in an interactive shell sends the text verbatim, including `? * $VAR > < ; & | ' "`.
- [ ] A leading-space `qq` invocation errors and never sends a stale history entry.
- [ ] `commit` and `qq` both honor `DOTFILES_AI_BACKEND` / `DOTFILES_AI_MODEL`; old `DOTFILES_COMMIT_*` names work with a stderr-only deprecation warning.
- [ ] `DOTFILES_QQ_TIMEOUT` (default 60s) and `DOTFILES_COMMIT_TIMEOUT` (default 15s) are independent.
- [ ] Backend runs outside the user's cwd, which is unchanged after `qq`.
- [ ] Stdout contains only the answer; all errors match the table above.
- [ ] `docs/DEVELOPMENT.md` updated; all tests and quality gates pass.
