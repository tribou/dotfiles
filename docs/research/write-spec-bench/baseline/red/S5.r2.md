# Split lib/commands.sh monolith into focused modules

## Summary

`lib/commands.sh` is 1,384 lines containing 61 functions and 135 aliases across unrelated domains (git, npm, docker, tmux, AWS, DigitalOcean, terraform, SSH, general shell utilities). This makes it hard to test in isolation, hard to review, and a source of avoidable merge conflicts. Split it into focused domain modules, following the lib module organization standard in #153 (boundaries, size, naming, load order). This is the first concrete application of that standard.

## Prerequisite (land first, with its own test)

Make `lib/index.sh` source underscore-prefixed (`_*.sh`) files **first and explicitly**, before any other module.

Under `en_US.UTF-8`, the current `ls`/glob ordering sorts `_shared.sh` 10th of 11, not first. Any split that introduces a source-time dependency on `_shared.sh` could silently break. Ship the ordering fix and a test that asserts the order before starting the split.

## Proposed split

| File | Contents |
|---|---|
| `lib/git.sh` | git aliases and functions (co, merge, branch management, commit helpers) |
| `lib/npm.sh` | npm/node detection and helpers |
| `lib/docker.sh` | docker/container helpers |
| `lib/tmux.sh` | tmux session and window management helpers (large, ~71 keyword hits) |
| `lib/cloud.sh` | AWS, DigitalOcean, terraform, SSH cloud helpers |
| `lib/repo.sh` | repo scaffolding: the `.gitignore` generator (~L712–745) and `mkrepo` |
| `lib/agent.sh` | agent state: the Claude keep-alive loop (~L375–388) and related helpers |
| `lib/commands.sh` | only what fits none of the above (general shell utilities) |

Boundary rules (per #153):

- `lib/cloud.sh` stays **one file** until it approaches the ~300-line cap, then splits by tool. Do not pre-split the small terraform/ssh pieces.
- `lib/repo.sh` must hold the `.gitignore` generator and `mkrepo`. They must not end up in the general `commands.sh` bucket.

`lib/index.sh` already sources `lib/*.sh` dynamically (globbing, excluding `index.sh`), so new files are picked up automatically.

## Constraints

- Purely a file reorganization. Do **not** change function signatures or alias names.
- Run `bashcheck` (the project linter, not `bash -n`) on each new file after splitting.

## Acceptance criteria

- [ ] The `index.sh` ordering prerequisite is merged, with a test, before the split begins.
- [ ] `just test-unit` passes.
- [ ] `just test` passes.
- [ ] All existing aliases and functions still work in a new shell session.
- [ ] `wc -l` on every `lib/*.sh` file is at or under ~300 lines (soft cap per #153).
- [ ] `_shared.sh` is sourced before every non-underscore module.
- [ ] `bashcheck` is clean on each new and modified file.
- [ ] The `.gitignore` generator and `mkrepo` live in `lib/repo.sh`; the Claude keep-alive loop lives in `lib/agent.sh`.

## Open question

`lib/tmux.sh` may exceed the ~300-line soft cap given how much tmux logic exists. If so, decide whether to split it per #153's rules or accept a documented exception.
