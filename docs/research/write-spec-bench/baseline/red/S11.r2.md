# refactor(packages): make mise the primary package manager

## Summary
Make mise the primary package manager for runtimes, language-level global packages, and Homebrew-managed formulae. Use mise tool backends (`[tools]`) for version-switched CLIs and mise's built-in `brew:` manager (`[bootstrap.packages]`) for formulae that still need Homebrew artifacts. Retain the existing Homebrew cask flow.

## Motivation / Context
- Default Node, Python, and Ruby packages are managed separately from `mise-config.toml`, while Homebrew owns a broader package set and bootstraps Ansible before mise is installed.
- Mise deprecates default Python package files (warnings from 2026.11.0, removal in 2027.11.0), so package behavior needs to move into TOML.
- Mise 2026.7.5 exposes `mise bootstrap packages`. Its built-in `brew:` manager installs Homebrew formulae into the canonical prefix without requiring Homebrew. `brew-cask:` exists but has narrower platform and lifecycle coverage.
- Making mise the orchestration boundary for residual Homebrew artifacts removes overlap and the separate Ansible Homebrew modules and Brewfile formula flows, and makes configured versions explicit.

## Architecture / Ownership
- `mise-config.toml` is the single source of truth for runtimes, bootstrap tools, standalone CLIs, language packages, and shared Homebrew formula artifacts.
- Naming conventions:
  - Standalone CLIs: canonical mise registry names.
  - Ecosystem CLIs: explicit `npm:` and `gem:` identifiers.
  - Isolated Python CLIs: `pipx:`.
  - Libraries that must be importable by the managed interpreter: Python tool-level `postinstall`.
- Ansible orchestrates installation and cleanup but does not duplicate the mise tool list in role variables.
- `[bootstrap.packages]` with `brew:` keys owns residual formulae in the shared Homebrew prefix.
- The Homebrew CLI and Brewfile flow are responsible only for casks (not moved to `brew-cask:` in this issue).
- Native OS package managers remain responsible for bootstrap prerequisites and system-level dependencies.

## Migration / Failure Handling
1. **Inventory** every formula in core, Linux-specific, macOS-specific, and optional declarations. Classify each as a `[tools]` candidate or a `[bootstrap.packages]` formula, recording the selected key and expected executable.
2. **Qualify** each `[tools]` candidate by installing it and running an executable/version smoke check on both macOS and Linux. Only dual-platform successes move to `[tools]`; the rest stay as `brew:` bootstrap packages.
3. **Greenfield bootstrap:** install the verified standalone mise binary and expose the checked-out `mise-config.toml` at mise's global config location. On existing machines, verify mise exposes `mise bootstrap packages` first; if not, reinstall/update via the verified standalone path.
4. Run `mise bootstrap packages apply --yes`, then `mise install --yes`.
5. Run the initial playbook through `mise exec` so mise-provisioned Ansible works without shell activation or Homebrew.
6. In Ansible, repeat package application and tool installation before smoke checks and before cleanup.
7. Move core and platform formula declarations into the repository mise config. Move optional formulae into the mise optional-config example (not silently into core). Leave only casks in the optional Brewfile.
8. After package application, tool installation, and smoke checks succeed, use an already-installed Homebrew executable to converge previously managed Homebrew copies of tools moved to `[tools]` to absent. Do not install Homebrew solely for cleanup. If any mise phase or smoke check fails, perform no cleanup and fail with package/tool context.
9. Surface targeted cleanup failures (including dependency-blocked removals) as actionable warnings without aborting unrelated provisioning.
10. Never run `mise bootstrap packages prune --manager brew`; it can remove manually installed formulae. Limit cleanup to the known formulae moving to `[tools]`.
11. Keep package and tool phases explicit in both bootstrap and Ansible so package, tool, and smoke-check failures remain distinguishable.
12. Add the canonical Homebrew prefix directly to shell `PATH` when it exists (`/opt/homebrew/bin` on Apple Silicon macOS, `/home/linuxbrew/.linuxbrew/bin` on Linux). Do not depend on `brew shellenv`: mise-installed formulae create shared-prefix links, not shims, and Linux may have no Homebrew executable.
13. Install or invoke the real Homebrew CLI only for the macOS cask flow. Linux formula provisioning must not require Homebrew.

## Requirements
**Language packages**
- Move default Node, Python, and Ruby gem package declarations into mise config.
- Use direct `npm:` and `gem:` entries for executable packages, `pipx:` only for Python CLI applications, and install `pynvim` via Python tool-level `postinstall` so `mise exec -- python -c "import pynvim"` succeeds.
- Delete the three legacy default-package files and remove their symlink, doctor, and goss assertions once represented in mise config.

**Formulae and tools**
- Audit every repository-managed Homebrew formula declaration (core, Linux, macOS, optional examples).
- Move portable version-switched tools to `[tools]` and retained formulae to `[bootstrap.packages]` with explicit `brew:` keys.
- A tool moves only after install and smoke check succeed on both macOS and Linux; on failure on either OS it stays a `brew:` package.
- Preserve floating channels: Node `lts`, Ruby `3`, and `latest` for standalone CLI and language-package entries unless a concrete compatibility constraint requires otherwise.
- Do not add `brew-cask:` entries.

**Bootstrap and cleanup**
- Greenfield bootstrap is mise-first: install standalone mise before Homebrew, provision Ansible through mise, and invoke the initial playbook through `mise exec` (or an equivalently reliable non-interactive mise environment).
- Install Homebrew later in the Ansible role only when needed for macOS casks.
- On existing machines, remove only formulae whose replacements are in `[tools]` and pass smoke checks; run cleanup only when a real Homebrew executable already exists.
- Treat dependency-blocked removals as surfaced cleanup failures, not silent duplicate ownership and not an abort.
- Use explicit phases everywhere: `mise bootstrap packages apply --yes`, then `mise install --yes`.

**Mise package semantics and support**
- Package application is explicit, `latest` accepts an already-installed version, upgrades use `mise bootstrap packages upgrade`, and formula pruning can remove packages installed by real Homebrew.
- The `brew:` manager supports Apple Silicon macOS and Linux x86_64/arm64, not Intel macOS. Apple Silicon is the only supported macOS architecture; no parallel Intel Homebrew formula path.

**Policy**
- Mise is the primary package manager for future additions.

## Non-goals
- Removing Homebrew entirely.
- Moving macOS casks to mise.
- Replacing native OS package managers for prerequisites or system packages.
- Exact-version lock maintenance.
- Generating mise config from Ansible variables.
- Splitting core managed tools across multiple mise config fragments.
- Intel macOS support via a separate Homebrew formula path.
- Using the repo's mise config as authority to remove unrelated manually installed formulae.

## Testing
- Each portable CLI migrated from a formula installs through `[tools]` and its executable/version command succeeds on macOS and Linux.
- Every residual `brew:` package applies and reports installed on its selected OSes without a Homebrew executable.
- A greenfield bootstrap reaches and executes the Ansible playbook without Homebrew providing Ansible.
- Cleanup runs only after successful package application, tool installation, and smoke checks; is idempotent; reports blocked removals; and never uses manager-wide prune.
- Canonical prefix paths work without `brew shellenv`; the Homebrew CLI is installed only for the macOS cask flow.
- Add focused Bats coverage for: single-source package policy, exact `[tools]` vs `[bootstrap.packages]` ownership, OS selectors, cask-only Brewfile content, bootstrap ordering, targeted cleanup safety, upgrade separation, PATH behavior, and removal of legacy package-file links.
- Update goss/integration assertions: representative runtime, standalone CLI, npm, pipx, and gem executables resolve through mise; `pynvim` imports from the mise-managed Python.
- Exercise the qualified tool set, `brew:` package status, and smoke commands in both Apple Silicon macOS and Linux CI paths.
- Assert the macOS CI runner is arm64 so a runner-label architecture change fails explicitly.
- In Linux integration, prove the `brew:` manager installs and exposes formulae without a Homebrew executable.
- Verify `just upgrade` sends formula upgrades and tool upgrades through mise and leaves only cask upgrades to Homebrew.
- Run the full install twice to verify idempotence across Ansible, mise, and Homebrew.
- Update `scripts/doctor.sh` so `[tools]` failures point to `mise install`, `brew:` package failures point to `mise bootstrap packages apply`, and no removed legacy symlink is expected.
