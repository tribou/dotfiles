# Add `ghv` command: fzf browser for combined issues and PRs

## Summary

Add a `ghv` shell command that lists all issues and pull requests for the current GitHub repository in a single fzf picker. Selecting an entry runs the matching `gh` view command (`gh issue view` or `gh pr view`) for that item.

## Background

Today, browsing work in a repo means running `gh issue list` and `gh pr list` separately, then copying a number into `gh issue view <n>` or `gh pr view <n>`. A single combined, fuzzy-searchable list removes that friction and lets the user jump straight to the item they want.

## Requirements

### Listing
- `ghv` fetches issues and PRs for the repo in the current working directory (via `gh`).
- Both are shown in one list, one item per line.
- Each line shows at minimum: type (issue/PR), number, title, and state. Labels, author, and draft status are optional but welcome.
- Type must be visually distinguishable (e.g. an `[I]`/`[PR]` prefix, or color).
- Default scope is open items. Closed and merged items should be reachable, via a flag (e.g. `ghv -a` / `--all`) or an fzf key binding.
- Ordering: most recently updated first.

### Selection
- Selecting an issue runs `gh issue view <number>`.
- Selecting a PR runs `gh pr view <number>`.
- Output is shown in the terminal as the standard `view` output. Passing `--web` through is a nice-to-have (e.g. `ghv --web`, or a key binding such as `ctrl-o`).
- Pressing Esc or Ctrl-C exits without running anything and returns a zero exit status (or the conventional fzf cancel status; pick one and document it).

### Preview (nice-to-have)
- fzf preview pane shows `gh issue view` / `gh pr view` output for the highlighted item.

### Errors and edge cases
- If `gh` or `fzf` is not installed, print a clear message naming the missing dependency and exit non-zero.
- If `gh` is not authenticated, or the directory is not a GitHub repo, surface the `gh` error and exit non-zero.
- If there are no issues or PRs, print a short message and exit without opening fzf.
- Titles containing tabs, quotes, or other special characters must not break parsing or the selection-to-command mapping.
- A failure fetching one of the two lists (e.g. issues disabled on the repo) should not hide the other. Warn and continue with what was retrieved.

## Implementation notes

- Use `gh issue list` and `gh pr list` with `--json number,title,state,updatedAt` (plus any optional fields) and `--limit` set high enough to be useful (make it configurable, e.g. `GHV_LIMIT`, default 200).
- Merge and sort with `jq`. Emit tab-delimited lines with the type and number in fixed leading fields so the selection can be parsed reliably (e.g. `fzf --delimiter '\t' --with-nth ...`).
- Fetch the two lists in parallel if practical.
- Follow the conventions of existing shell commands/aliases in this dotfiles repo for placement, naming, and sourcing. Check how similar `gh`-based helpers are defined before choosing a location.
- Add `jq` to the dependency check if used.

## Acceptance criteria

- [ ] Running `ghv` in a GitHub repo opens fzf with issues and PRs interleaved, sorted by last update.
- [ ] Each row clearly indicates whether it is an issue or a PR.
- [ ] Selecting an issue row runs `gh issue view <n>`; selecting a PR row runs `gh pr view <n>`.
- [ ] Cancelling fzf runs nothing and exits cleanly.
- [ ] Missing `gh`, `fzf`, or `jq` produces a clear error and non-zero exit.
- [ ] A repo with no issues or PRs prints a message and does not open fzf.
- [ ] Titles with special characters display correctly and map to the right item.
- [ ] If one of the two fetches fails, the other list is still shown with a warning.
- [ ] Usage is documented (help text via `ghv -h` and/or a note in the repo's docs/README).

## Out of scope

- Creating, editing, commenting on, or closing issues and PRs.
- Cross-repo or org-wide listing.
- Caching of results between invocations.

## Open questions

- Which shell(s) must be supported (bash, zsh, both), and where do existing helper functions live in this dotfiles repo?
- Should the exit status on cancel be 0 or fzf's conventional 130?
- Should closed/merged items be included by default or only behind a flag?
